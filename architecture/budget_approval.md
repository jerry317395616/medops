# Budget submission, aggregation and human approval — COD-032

This slice is in progress. Budget planning is delivered; submission and financial approval are not yet delivered. ADR-0029 defines the intended boundary.

Department submissions seal facts from a frozen plan. Consolidation selects approved department submissions within the same company, hospital, published organization snapshot, fiscal year, currency and precision. Each line retains its original plan/line, unit, account, budget subject, funding, project and period. Duplicate original facts and nested consolidations are rejected.

Approval cases are separate from financial snapshots. A case captures the matrix decision, delegation evidence and source digest. Human decisions advance sequential All/Any steps and create immutable review records. Rejection followed by a new request creates another case round. Direct model writes and native workflow calls cannot bypass the governed adapter. An approval does not create an available budget or post ledgers.

Matrix version1 keeps its two-decimal currency column, original serialization, digests and historical receipts. Version2 captures0–9 precision, stores thresholds as exact decimal strings in a separate column and rejects binary floats. New evaluations compare actual captured source precision and exact source values. Their decision digest binds the amount and context. Legacy policies retain their digest when reused with exact evaluations; exact policies do not change version1 evaluation behavior. New exact budget approval targets require the exact evaluation contract.

The exact amount foundation and legacy migration proof are verified. Department sealing now implements two typed models, the source-locked service, three bounded APIs (FIN-025–027), and an entry from frozen plans in the planning page. Its verification is in progress. A department submission is created and submitted atomically as a Sealed, immutable financial snapshot, not a financial approval. One original frozen plan can have one sealed snapshot; later rejected approval rounds reuse that snapshot rather than copying or editing facts.

The sealing service checks the selected plan's complete current source/field permission and create/submit scope. With the hospital and version locked, it recomputes the frozen version proof using the bounded, ordered original plans. Other departments' documents are read only for this internal integrity calculation and are never returned or logged. The original whole-version digest remains at field level1 in both parent and child; the public snapshot omits it. A department reader does not need another department's read permission merely to submit its own included plan. Reads, titles, lists and durable replay recheck the selected source and fields; lists paginate only complete authorized snapshots.

The detail API also supplies current display names for units, budget subjects and funding sources after an explicit field-read check. Unreadable names are omitted; the stable authorized identifier remains the fallback. These display labels are not sealed financial facts and do not change the snapshot digest. The page sorts periods for reading, renders values as text and keeps source proof in a separate expandable section. Native form permissions verify a fresh full document after Frappe strips private fields, without restoring those fields onto the response.

Human confirmation, approval/review models, aggregation from approved departments, workflow/ToDo adaptation, the approval UI and full concurrency verification remain required before completion. Installation defines metadata and indexes without assigning user roles, scopes or shares. Sealing uses existing budget roles and creates no available budget, native ERP Budget, GL Entry or Stock Ledger Entry.

The source integrity scan uses COD-031's bounds of1000 plans and50000 total source lines; a department snapshot has at most5000 lines and captures0–9 precision. Totals use a bounded15-integer/9-fraction exact string, with no binary-float conversion. Current facades cap5000 candidate submissions and100 rows per response, fail closed on overflow, and do not expose hidden candidate counts. Hospital-scale performance validation remains an explicit release gate.
