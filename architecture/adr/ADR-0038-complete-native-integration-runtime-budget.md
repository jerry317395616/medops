# ADR-0038 完整原生集成校验的执行时限

## 背景与问题

普通与 IONE Core 两套原生集成作业当前各限90分钟，包含固定 fork 的完整 Bench、全量应用测试、标准单元用例、额外已提交并发站点及三个环境的完整性检查。

2026-10-28，产品cebf623的[完整 CI40656055185](https://github.com/jerry317395616/medops/actions/runs/40656055185)通过全部门禁，普通集成作业77.083分钟（08:21:39至09:38:44 UTC），612项主套件3645.756秒、25项单元73.938秒、已提交并发探针217.400秒，另有安装、迁移及环境检查。之后[受控释放专项40660621810](https://github.com/jerry317395616/medops/actions/runs/40660621810)的两项扩展事务用例1118.036秒，包含真实合成来源、确认/过账、反复回放与故障注入。还需增加已提交数据的释放竞争和释放后额度再使用。

这些是不同负载的 CI 样本，不能相减后当作精确预测或医院容量。它们足以说明旧时限的余量不足以可靠容纳新增必需验证；超时不能证明业务错误，也不能计为验证通过。

## 决策驱动因素

保留完整原生权限、事务、不可变证据及并发覆盖；所有必跑作业均须成功；CI 执行仍有明确上限，新增耗时可审计，不改变生产配置或业务超时。

## 备选方案

1. 保持90分钟：资源上限较低，但新场景可能让完整校验在产生结论前终止，需要调查和重跑。
2. 按模块拆分原生作业：可降低单作业耗时，但增加多套 Bench 开销，并需先验证共享夹具、全局状态和覆盖集合的等价性。
3. 将两个集成作业提高到120分钟，保持完整套件和门禁：增加最大资源预算，能先保留已有验证语义；采用。

减少场景、跳过失败用例或用纯替身替代原生财务事务，不满足本任务的验收要求。

## 决策

仅将 `Integration` 和 `Integration with IONE Core` 的 `timeout-minutes` 从90设为120。Quality、Security、Required、权限、依赖版本与锁定、测试内容、跳过拒绝、Error Log零检查及 Required 对全部结果的判断保持其既有要求。

不取消旧版本正在运行的作业，也不把观察超时当成停止依据。新时限只适用于以包含本决策和工作流的提交启动的新运行。任何真实超时、失败或缺证仍按其原始结果记录；禁止把重跑前的失败从证据中抹去。

## 后果

每套集成的最大执行预算增加30分钟；运行仍可能因业务错误、环境故障或超时失败。需要分别保留源码、测试数量、耗时及最终结论，避免把不同提交的结果混用。以后若完整流程接近120分钟，应先测量与优化，或重新评审可靠的分组执行，而不是持续增大时限。

## 验证与退出条件

本地验证两套集成均为120，其余门禁未改变，并运行完整质量、治理和校验和检查。新提交的普通及 Core 全套必须结束并通过 Required，不能用非门禁专项替代。若采用模块分组，应另立决策，证明完整发现、状态隔离、失败传播和覆盖集合仍符合要求。

## 迁移与回滚

无数据库或服务器迁移。回退工作流时限会恢复90分钟，但可能使同一完整套件超时；须按原结果保留证据。不得因回退而删除有效财务事实、减少测试或跳过 Required。已接受 ADR 按仓库不可变规则保留，未来决策只能通过正式取代关系更新。

## 安全与合规

工作流继续只读仓库权限、固定供应链校验和与用户 fork。专用并发数据仅在 GitHub RUNNER_TEMP 内的固定命名新站点创建；不访问维护中的服务器。生产请求、数据库锁或确认凭证有效期均不随 CI 时限改变。
