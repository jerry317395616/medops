# ADR-0040 跨页面和会话的预占决定恢复

## 背景与问题

ADR-0039 的人工页面只在内存保存凭证及已确认决定的引用。刷新、重新登录或未知提交结果之后，用户可能不知道此前是否已预占。重新生成随机分摊会把结果调查变成另一项业务操作；恢复旧凭证又会绕过会话及到期边界。

## 决策驱动因素

保留不可变独立证据、真实网页会话、当前角色/范围/字段授权与到期后重新人工核对。恢复应先发现事实，不能暗中创建、重放或续期财务操作。

## 备选方案

1. 把凭证和命令写入浏览器持久存储，刷新后自动继续：拒绝。
2. 解密或重发旧会话的预览凭证：拒绝。
3. 在当前已授权来源和预算围栏内读取原决定、完整续期与已核验根，重新核对后再按原协议操作：采用。

## 决策

新增默认关闭操作总开关之下的 `reservation_operations.recovery` POST 只读接口。沿用既有管理角色及原生网页认证，拒绝令牌、访客、后台和嵌套事务；使用既有清洁 READ COMMITTED 边界。要求当前原生来源字段权限、预算下达读取范围与预占写范围，数据范围不因恢复而扩大；具备这些权限的当前管理人员可读取该范围的待办引用，原操作者仍保留在历史证据中。

请求包含来源快照、摘要及一个完整预算键。先执行已有完整采购/预算检查，再在已持有来源和预算围栏中枚举该来源及原始组织的全部原决定，最多100条，逐条验证独立确认/决定投影后才按所选预算键过滤。按原确认、原决定及完整续期链确定当前有效期；不能只看原决定旧时间。每页最多20条，后续页必须带完整目录摘要，指定单个决定时也必须重新完成同一范围的核验。上限是拒绝边界，不是医院容量结论。

若存在根，必须与初始完整检查的位置一致，并重新核验全部物理历史和独立确认证据；只返回可查看的既有结果。无根且原来源快照不再一致时禁止续期。来源未变但上一决定未到期时只显示有效期；到期后返回原意图中恢复所需的金额、币种、精度、日期、理由和分摊引用。任何缺证、重复、投影篡改、范围/字段权限变化或目录变化均拒绝；不把目录结果当作资金可用额或写入授权。

接口不读取旧幂等密文，不返回或生成 proof、proof_hash、session_digest、私有快照 JSON 或一次性键，不修改原决定、根或回执。当前会话变化后仍可在当前授权范围内查看事实；新续期必须在最新决定到期后重新生成确认，由当前人类明确勾选并使用新会话凭证，原领域协议不变。

页面选定来源及预算后先核验历史。已有记录不能隐式变成另一随机分摊；用户须选择恢复/查看，或明确选择新增独立分摊后重新核对。恢复按钮先重新读取指定决定，若并发操作已经产生根则转向查看；不会再生成另一预占。尚未核实的页面内命令继续保持原命令/键，只读恢复不自动清除其不确定状态。后台操作完成后返回页面时，明确路由要求的预占优先于记忆中的上次结果，后者保留显式查看入口。

## 后果

无需新增财务表、角色、分享或标准证据权限；增加受控只读服务和目录核验成本。它依赖原有受控不可变存储及协作写入口，不能证明外部越权 SQL 删除或非协作写入。已取消、已变更或当前不可授权的原生来源不获得恢复捷径。未确认的孤立预览没有财务授权，不恢复其凭证。

## 验证与退出条件

纯解析覆盖摘要、范围、未知凭证和分页边界；原生临时证据表覆盖独立投影、缺证、目录到期漂移、撤权及无幂等写入；专用一次性 CI 的真实已提交来源/预算/控制器通过实际 Cookie HTTP 验证到期前状态、跨会话恢复、最新续期有效期、已释放根结果和无旧凭证输出。前端执行实际页面脚本，验证恢复后仍需未勾选确认、并发已过账转向查看、核验失败阻止新建、独立分摊明确选择和导航优先级。控件/DOM 替身不是原生浏览器验收，仍须真实 Desk、权限矩阵、全部写入口及医院容量验收；生产开关不自动开启。

## 迁移与回滚

没有新模式迁移，依赖既有独立证据表与索引。未来部署需正常更新应用、构建资产并刷新页面缓存，维护期间不访问服务器。回退先关闭操作入口，移除恢复页面入口和适配层，保留全部原始/续期/释放证据、财务根、事件和幂等回执及兼容历史读取器。不得删除已经发生的事实来简化恢复。

## 安全与合规

恢复是当前授权下的只读事实查询，不能充当原会话或新财务动作的许可。服务和钩子无提交、外部调用或自动确认；不记录理由、快照或凭证。沿用认证前 MedOps 诊断隐私保护。所有生态依赖继续使用用户锁定 GitHub fork，不修改上游。
