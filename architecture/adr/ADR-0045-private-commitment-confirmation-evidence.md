# ADR-0045 独立采购承诺授权证据与来源时间下界

## 背景与问题

ADR-0044 的结构意图仍不能证明独立确认或受控持久化。确认还不能早于当前采购申请/订单父行与子行的最新修改时间，否则可以把后来的来源版本套进较早的确认窗口。已规划的 HRP Budget Commitment 是业务对象蓝图，本阶段不将其改作授权记录，也不因此开放 Commit 写入。

## 决策驱动因素

独立、不可改写的确认和决定；保持原预占、原事件和原订单摘要；操作者、会话、最长五分钟窗口及明确人工确认；当前来源与前驱绑定；通用权限配置不能自动开放私有协议；先验证存储结构，再接入真实受控事务。

## 备选方案

1. 复用释放表或把通用业务单据的提交状态当作承诺确认：动作、来源和证据语义不同，拒绝。
2. 在原根或已存在决定中追加可变状态：改写历史，拒绝。
3. 新增独立私有授权证据模型，绑定完整意图和来源时间下界，再建设受控决定/事件事务：采用。新表和纯证据函数不代表财务转换已完成。

## 决策

新增 HRP Budget Commitment Authorization，标准权限为空、不可提交/取消/重命名/修改，确认与决定均为追加记录。预算范围、根和前驱、订单行稳定身份、订单标识、当前申请和订单摘要、来源最后修改时间及私有快照与意图列完整对应。订单标识使用受核验的 Data，不用预览记录的 Link 阻断尚未形成承诺事实时的原生订单生命周期。查询和逐条权限钩子拒绝标准用户访问，即使额外 Custom DocPerm 配置了读写权限；受信数据库管理员不属于此协议的授权边界。

采购承诺意图采用显式 v2，新增 source_modified_at，为当前申请/订单父、子修改时间的最大值，规范为无时区微秒文本。v1 只曾用于未接线结构组件，没有已部署持久化证据；新模型拒绝 v1 意图，不自动转换或补填确认时间。采购订单来源快照及其原有 v1 摘要/稳定行身份保持不变；原预占、续期和释放协议不变。

Confirmation 绑定意图、根、当前操作者、凭证摘要、会话摘要、记录与到期时间。记录时间同时不早于前驱及 source_modified_at，窗口大于零且不超过既有五分钟策略。Decision 只能由相同确认、操作者、会话、凭证及窗口构造，必须 acknowledge is True；当前时刻须位于半开有效区间。数据库唯一约束覆盖证据键、确认引用、事件摘要和根/前驱派生的承诺后继键。不同授权表的唯一性不证明释放与承诺互斥，仍须完整前驱核验、共同预算锁和事件序号约束。

行校验核对所有物理列、私有规范 JSON、原生日期/微秒时间表现、来源身份/版本/范围和来源修改下界。摘要和自洽快照不证明记录来源、历史完整性、先前授权、当前权限或跨根订单分摊；这些必须由后续独立读取器和事务服务重新核验。原始凭证不落表，凭证和会话摘要不进入默认 repr。

本阶段控制器拒绝全部真实模型写入，配置开关、ignore_permissions、db_insert/db_update/db_set 等不能获得写入权。后续实现必须以标准控制器和精确事务内私有许可追加独立决定、承诺事实及事件，完整回滚失败；不得用测试临时表写法绕过真实控制器。真实人工确认、受控持久化、跨根额度、混合历史/旧回执、来源生命周期和实际转换仍须完成。

## 后果

设计模型从405增加至406，运行模型从47增加至48；新增私有证据表及索引，不改变现有业务蓝图或财务事实。增加必要的来源与时序验证成本。安装/迁移不会开启写入或授予新角色。标准管理员或直接 SQL 能控制数据库，不能据纯摘要宣称具备外部数字签名或对抗数据库管理员的不可否认性。

## 验证与退出条件

纯测试覆盖 v2 规范化、伪造/重复/未知 JSON、来源和前驱时间、有效期、换人/换会话/换意图/换凭证、严格布尔确认、同前驱唯一后继、全部列与私有快照对应及 repr 隐私。隔离原生测试验证真实新表、InnoDB、完整列/索引、全部控制器写路径拒绝；连接私有临时副本验证往返和唯一约束，并验证额外权限下标准查询/逐条读取仍拒绝。临时数据不证明实际人类或真实授权写入。受控持久化、撤权/回滚/并发、原生 HTTP/UI、普通/Core 完整回归及医院验收仍是最终闭环要求。

## 迁移与回滚

仅新建独立表/索引，既有 HRP Budget Commitment 蓝图不变；无旧记录改写或凭证回填，服务器维护期间不执行迁移。当前真实写入永久关闭，可回退代码并保留空表及原有财务数据。以后产生有效授权或 Commit 事实后，须先关闭相关入口，保留全部证据、回执及兼容读取器，不能直接回退到释放专用历史读取或删除承诺记录。

## 安全与合规

标准角色无新授予，不增加公开写 API、自动确认或外部系统调用。私有来源和理由不得进入日志或默认展示。全部框架/ERPNext/HRMS/Core 来源保持用户 fork 与锁定版本，不修改上游。全医疗平台及医院上线的财务口径、容量、接口和现场业务验收仍须独立完成。
