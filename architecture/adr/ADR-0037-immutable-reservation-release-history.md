# ADR-0037 不可变预占根与独立释放证据

## 背景与问题

当前首笔预占把受控来源、独立人工决定及第一条事件冻结到已提交根单。根单的金额、事件数量和链尾描述首笔事实。直接修改这些列来表示释放会改写已经提交的财务证据，并使原授权失去核验依据。仅追加带有自算摘要的事件同样不能证明释放获得了授权。

## 决策驱动因素

保留首笔事实和独立授权，禁止重复释放或过期状态分叉；精确金额、单事务、统一来源和预算锁、可审计幂等，以及复用锁定 Frappe 的标准文档控制器。

## 备选方案

1. 更新已提交根单的余额与链尾：违反不可变约束，拒绝。
2. 新建可变余额表作为独立权威：需要维护另一套可改写状态及一致性协议，暂不采用。
3. 冻结根单，追加与独立释放决定绑定的事件，并核验全部物理历史：采用。

## 决策

根单始终保留首笔投影。当前状态由首笔预占和后续独立授权的释放事件推导，不把根单历史列当作当前余额。原版与续期版首笔事件仍按原有摘要及全部原始授权、续期证据核验，不改旧摘要版本。

释放意图必须绑定根标识、原预占意图摘要、原来源快照摘要、全部预算键、币种精度、前序事件序号和摘要及时间、当时未结预占、正数释放金额和理由。本阶段仅支持未转承诺/实际的预占；释放不得超过当时未结金额，不支持增加预占或重新打开已释放的同一分摊。

独立 `HRP Budget Reservation Release` 表记录 Confirmation 与 Decision，完整意图保存在受保护快照中。确认凭证只存摘要，绑定当前操作者、会话和最长五分钟窗口；明确确认后才能构造决定。唯一后继键绑定根及前序事件摘要，数据库唯一索引禁止同一状态出现两个释放决定；确认引用本身也唯一。预览允许并存，只有过账决定消耗后继键。

释放事件沿用原始采购来源各标识及快照修订，将 `source_action` 固定为 `Release Reservation:` 加决定标识。决定标识由完整意图和确认证据构造，事件原有摘要已覆盖该字段。因此无需改变旧事件列或旧版摘要；读取器须独立重建决定和事件，并检查来源、金额、前驱、序号、操作者及时间窗口一致。摘要本身不证明真实人或受控存储。

未来事务必须在同一事务追加 Decision 与释放事件，任何失败整笔回滚。完整读取器须按根核对所有物理事件及所有已过账释放决定，拒绝单边缺失、重复、分叉、未知事件及超界数据；不能只查事件已引用的决定。确认预览未执行不构成孤立过账。共享预算锁、来源及当前授权应贯穿预检、写入和最终核验；业务领域服务不得提交。

## 后果

增加一张无标准角色权限的独立证据表及有界完整历史核验成本。根单历史金额不能作为后续余额接口。当前仅实现纯契约、供后续适配使用的完整历史核验及禁止写入的模型；数据库共同围栏内的读取适配、受控写入、审计幂等、HTTP/UI 和真实并发仍须完成，不能生产启用。

## 验证与退出条件

验证部分至全额释放、精确金额、原版及续期版原始决定、状态过期、换人/换会话/凭证失效、分叉和证据缺失，以及实际数据库唯一约束。开放写入之前还必须验证原生来源、共同锁、单边插入失败全回滚、撤权、跨进程释放竞争、旧首笔回执在释放后的重放、真实人机界面与医院验收。现有每链10000事件上限是拒绝边界，不是医院容量承诺。

## 迁移与回滚

只新增独立证据表及索引，不更新既有根单、事件、财务或库存分录。服务器维护期间不迁移。部署前须在隔离副本验证，并统一停用相关新旧写入及 worker。当前模型没有业务写入，可回退新代码并保留空表；未来一旦存在有效释放事实，旧读取器可能拒绝后续事件，必须保留全部证据并准备兼容读取方案，不能直接回退或删除释放行。

## 安全与合规

不新增用户角色、分享、公开 API 或自动财务操作。凭证、会话摘要和意图快照不进入日志或通用序列化。确认与决定本身不能授予预算、来源或组织访问权；服务须使用当前角色及范围校验。所有生态来源继续使用用户 GitHub fork，禁止修改上游源码。
