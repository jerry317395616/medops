# ADR-0027 核心工作台的真实统计来源、质量历史与导出授权

## 背景与问题

八张核心报表中七张只有通用设计占位，首页只有导航。当前质量问题是可变状态，无法据此推导历史新增量；共享的 ERP 主数据也不能自动归属每家医院。COD-201 已补齐基础访问边界。

## 决策驱动因素

真实来源和完整权限优先，优先复用官方生态应用的标准入口；可重复迁移、事务一致和可核验口径是交付前提。

## 备选方案

1. 从当前状态和全球目录直接生成所有统计：无法证明医院归属，也无法还原历史，拒绝。
2. 只增加前端报表和导出按钮：无法控制后台、邮件及直接接口的读取，拒绝。
3. 采用显式登记、实际采集事件和标准报表，并在服务及导出端核验当前权限，选用。

## 决策

沿用一个 medops 应用和现有模块。复用 Foundation 的 HRP Reference Link 蓝图，登记医院实际使用的五类标准主数据；服务拥有写入权限，使用批次、修订、唯一身份、幂等和事务，不修改 ERP 标准记录，也不自动登记全局目录。登记台账及业务日期的有效区间是当前登记口径，不宣称历史时点快照。

Master Data 新增 HRP Data Quality Event，只追加实际状态事件。全局 Epoch 仅保存采集起点；现存问题在迁移时形成当前基线，不推测过去的检测和解决时间。问题写入、历史事件及幂等结果在同一事务内成功或回滚。每个问题修订只产生一个事件；原始值不进入历史模型。历史读取还须通过当前问题的全部来源字段授权，不能利用历史回放绕过撤权。

实现完整八张标准 Script Report：组织版本差异、组织标准映射、变更时效、重复值、外部映射完整率、质量历史趋势、委托到期和职责初筛。组织差异必须取得两个完整已发布快照；时效使用实际提交复核时间；重复及完整率分母使用明确登记与当前授权；职责初筛复用原有管理角色和真实单据服务，不授予执行权限。质量趋势以数据库权限子查询和 SQL 聚合读取历史，不设置生命周期事件总量上限；缺少完整历史授权则拒绝，不能把被过滤的事件画成零。

复用 Frappe Page、Workspace、ToDo 和报表导出。工作台各栏只作有界预览，不从预览推导全院总数。保留当前原生、范围、来源字段、遮罩和导出权限检查。禁用准备报表缓存，避免复用撤权前结果。

接受仅针对八张核心报表的 `override_whitelisted_methods` 导出适配：原同步/后台导出入口对过滤条件强制加入导出标记，随后调用锁定版本原函数；后台参数保留该标记。无 HTTP 上下文的报表执行默认按导出检查，覆盖邮件和后台执行；其他报表原样委托。客户端只能请求更严格检查，不能把导出降为普通读取。使用标准 Report 校验钩子禁止准备缓存，并以 extend_doctype_class 在原权限检查前仅将核心报表及其自定义派生报表的内存 prepared_report 置零，防止旧配置复用撤权前结果。拒绝增加未声明关联来源的自定义列；隐藏和重排列不受影响。导出识别规范化报告名称及自定义父链，非标准交互读取按导出处理，覆盖 HTTP 内的邮件生成。不改写上游源码，不使用 override_doctype_class。

## 后果

新增两个运行模型，其中关联登记复用原蓝图，质量事件增加一份蓝图。通用列表不能检查来源字段，登记与历史通过受控服务查询；历史报表要求完整历史授权。查询超出保护界限时明确要求缩小条件，不能截断后输出精确总量。医院实际容量和性能仍须按确认规模验证。

## 验证与退出条件

验证八张报表真实数据、空与过量输入、版本完整性、源权限及字段、撤权后查询和同步/后台/邮件导出、跨院与科室、登记批次原子性和修订、历史基线和转换、同键并发、事务回滚及重复迁移。标准入口与受控 API、工作台待办及服务时限必须实际运行。完成全部质量、受保护 CI 和隔离推广后才登记最终验收。

## 迁移与回滚

先备份、暂停本项目任务并进入维护模式。新增表和索引后建立 Epoch 与基线；重复迁移不重复基线，不更改既有业务值、次数和业务时间。回退保留登记、事件、授权字段及幂等记录；如旧代码存在已修复的越权，维持维护模式，修复后再开放，不能以删除历史或关闭权限校验解决错误。

## 安全与合规

不保存原始观察值，不修改财务或库存台账，不自动扩权。服务审计只记录报表编号、数量、状态和摘要。当前医院专项接口、容量、UAT、备份恢复和全 HRP 业务闭环仍为独立上线闸门。
