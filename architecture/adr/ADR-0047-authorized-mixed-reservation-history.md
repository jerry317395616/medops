# ADR-0047 独立承诺事件与原预占回执的完整混合历史

## 背景与问题

承诺记账不能使原预占、续期回执或预算核查失效。仅在原释放专用读取器之外添加 Commit 写入，会导致之后的完整历史被拒绝。真实初始单据使用 budget-reservation-root-v1 对来源分摊标识派生根名称；先前未接线承诺构造器误把来源分摊标识自身当作根名，早期手工结构夹具没有发现该差异。没有真实承诺记录或服务器部署，须在受控写入前修正并以实际初始单据检验。

## 决策驱动因素

原根和确认不可修改；每个后继事件独立授权；普通和续期原回执兼容；完整范围与反向父查询发现孤立决定；一次有序核查避免重复回放全部前缀；未完成实际转换继续严格拒绝。

## 备选方案

1. 改写原预占或原确认来容纳订单：破坏历史，拒绝。
2. 新增 Commit 写入但保留仅释放历史读取：使旧回执和后续预算判断失效，拒绝。
3. 在接入写入之前，建立独立承诺事件契约和混合历史读取，统一原回执与预算核查：采用。

## 决策

承诺意图使用与实际初始标准文档完全相同的确定性根名派生，拒绝以来源分摊标识替代根名。不转换或回填早期未持久化的结构夹具意图，也不修改已有真实根、确认或事件。

Commit 事件保留原 Material Request 的来源谱系，包括原快照摘要、行和分摊。source_action 为 Commit: 加独立决定名称；该决定及其独立确认完整绑定采购订单名称、行、稳定身份、规范订单与当前申请快照、金额、前驱、操作者、会话和有效期。事件必须与精确决定、前驱和窗口一致，沿用现有事件存储格式，不把订单名称替换进原根来源。来源谱系不是订单当前权限或累计分摊证明。

完整核查同时验证初始/续期授权、冻结根和每个 Release Reservation 或 Commit 的独立确认/决定。重复确认、同前驱两个决定、缺事件、缺决定、缺确认、错动作/金额/操作者/快照/范围、未知事件及不完整集合均拒绝。所有结构链只回放一次，另核查首事件并增量维护余额；不能用重复遍历全部历史前缀替代有序完整验证。

原生私有读取在已有预算锁和当前台账字段/组织权限边界内，分别按完整范围和已知父标识查询承诺决定，含零事件或范围错误的孤立记录。按真实事件种类读取两个独立证据表；某一类预期为零也执行物理决定查询。普通/续期原预占回执、完整来源授权观察和释放状态读取使用相同的混合历史契约。既有仅释放契约默认仍不接受无独立证据的 Commit。

允许在独立验证 Commit 之后释放剩余 open_reservation，释放意图和原有哈希格式不变，不能释放 open_commitment。Actual 和 Release Commitment 仍没有独立授权协议，因此继续拒绝。承诺证据控制器仍拒绝真实写入，没有 Commit 写入许可、新 API、自动确认或界面按钮。

## 后果

无新模型、字段、权限、配置开关或历史迁移；依赖 ADR-0045 的既有私有证据表及索引。新增私有读取使完整核查增加必要数据库访问。若新表或索引缺失则拒绝，不降级忽略承诺事实。保留原台账/MR 当前权限检查，订单快照只在私有核查中使用；真实承诺准备和过账仍须独立验证当前 PO 权限、共同父预锁、完整成员及跨根累计额度。

## 验证与退出条件

纯测试验证真实初始根派生、混合释放/承诺、旧确认保持、来源进展与经济事实拒绝、事件/凭证/时间篡改及线性回放。隔离原生临时副本覆盖普通与续期根、完整预算观察和原回执历史、缺失/孤立/范围错误/私有快照篡改、跨动作同前驱及101个范围的分组读取；真实提交的申请/订单用例从实际初始事件构造承诺意图。临时表证据不证明真实控制器已写入或真实人已确认，必须继续完成受控持久化、全局分摊、来源生命周期、原子 Commit/实际转换、人工 HTTP/UI 和医院验收。

## 迁移与回滚

无新迁移或历史改写，维护期间不连接服务器。当前无真实 Commit 写入，可回退代码并保留既有财务事实。以后产生 Commit 事实后，回滚必须保留兼容混合历史读取器，不可恢复只认释放的读取、删除证据或改写冻结根；应先停用写入口并按受控追加/冲销协议处理。

## 安全与合规

没有新增角色授权、公开接口、自动批准、直接账本写入或事务内外部调用。原始凭证不落表，私有快照和理由不进日志。Frappe/ERPNext/HRMS/Core 源码不变，来源仍为用户 fork 和固定版本。医院真实容量与现场业务口径尚未验收。
