# ADR-0049 完整采购承诺准备与私有确认标准控制器追加

## 背景与问题

额度观察仍要求调用者提供完整来源和预算键，不能直接接入真实确认保存。确认记录不能只凭配置开关或客户端传入的快照写入。当前采购流程还可能在同一申请上留下多个仅状态/时间不同的历史快照，严格单版本发现会提前拒绝合法历史，但也不能把允许发现不同版本等同于允许财务事实变更。

## 决策驱动因素

锁前完整发现、一次共同锁、锁后独立核验；真实标准控制器写入；当前操作者/会话/原生权限；不可改写历史；确认不是决定；明确默认关闭边界；真实源和真实表的验证。

## 备选方案

1. 把额度观察当作写入许可或由客户端提交来源/预算集合：缺少原生来源与集合完整性，拒绝。
2. 配置为 true 后直接允许标准 SDK 创建证据：没有精确事务内许可，拒绝。
3. 新增完整准备状态，再以同一对象、精确行和私有上下文通过标准控制器追加一条 Confirmation：采用。

## 决策

准备服务首先验证 POST 网页会话、当前管理角色、选定根的原始独立授权及原生 PO 读取/字段权限和申请行链接。锁前迭代收集相关订单分配、来源、来源全部物理预占的预算键和各预算范围发现的其他来源，直到集合稳定；键与来源均遵守现有上限，规范名称别名、超限或不收敛拒绝。之后一次预锁完整 MR 父集合和订单父，再取得完整预算锁，重新核查全部来源/物理事件/独立历史、当前订单快照、精确意图和全局额度。任何晚发现变化须完整回滚重试，不能补取预算锁。

历史发现可显式采用身份加确定性版本标记，不再要求同一申请的全部历史快照摘要相同。该标记从不证明授权；锁后每个完整原始快照仍须单独与当前来源比较，经济事实变更拒绝。默认严格发现保留原有冲突拒绝。初始预占写入的单版本/分摊去重限制保持不变，不借本次读取扩展允许跨版本重复初始分摊。

LockedCommitmentState 绑定完整检查上下文、原生订单、承诺意图、额度观察、操作者和专用会话摘要，字段默认不展示私有数据。完整操作入口和出口重验所有独立历史与额度；标准控制器每个阶段刷新当前角色、网页会话、台账字段/范围和根写范围、原生 MR/PO 当前版本与事务见证，不能把旧状态对象当作权限缓存。

仅在 medops_internal_commitment_confirmation_enabled 严格为 true 且持有私有精确上下文时，标准控制器可对一个固定文档对象追加一条 Confirmation。确认绑定当前意图、来源时间下界、当前用户/会话、随机凭证摘要及最长五分钟窗口；原始凭证不落表、不进入默认 repr。所有业务列、文档身份/新建状态/所有者与规范行完全相等，写入后重新读取并验证实际持久化行和完整原生状态。缺少上下文、换对象、改字段、过期或失权均拒绝并使预算事务失效。服务/控制器不自行提交事务，失败需完整回滚。

Decision、Commit/Actual 事件、修改、删除、重命名、取消及标准 SDK 权限仍关闭。新增开关默认不存在即关闭；没有公开 API、自动批准或对管理角色的原始证据权限授予。当前私有准备函数尚无域服务审计/幂等包装，因此不能作为外部接口暴露，后续必须补齐。

## 后果

没有新表、字段、索引或角色授权；只更新既有私有模型说明及控制器。确认追加是独立可回滚的预览记录，不改变冻结根、原始确认/续期或财务事件。完整核查有额外开销，性能和真实医院容量仍须验证。其他原生写入口和 PO 生命周期共同围栏、原子决定/Commit、实际转换及人工界面尚未完成，不能据确认追加宣布财务闭环或 HRP 可上线。

## 验证与退出条件

原生普通用例覆盖跨预算完整发现、无晚取锁、规范别名/上限拒绝、既有预算锁禁止升级，以及多个非财务来源版本的逐个核验和经济变更拒绝；配置打开也不能获得通用写权限。扩展精确隔离的已提交探针，在实际发布预算、原始/续期根、真实 MR/PO、真实证据表及标准控制器上验证默认关闭、实际追加/提交/回滚、过期后整笔回滚、不可改写与根/财务事实保持。探针用户会话和时钟为合成测试，不代表真实人或人工 HTTP/UI 已验收；临时表用例不能代替真实持久化。全部本地质量、普通/Core 原生和完整回归仍须通过。

## 迁移与回滚

无结构迁移；部署时仅常规元数据同步，维护期间不连接服务器。回退前关闭新增开关，保留所有已生成确认、凭证摘要和既有财务事实。当前没有新承诺决定或事件，确认不应被改写成决定或删除；未来产生 Commit 后必须保留兼容混合历史读取器，按受控追加/冲销处理。

## 安全与合规

只使用用户 fork 的固定 Frappe/ERPNext/HRMS/Core，不修改其源码，复用原生采购与标准文档控制器。无直接 GL/SLE/Bin 写入、无事务内外部调用；原始凭证、快照及理由不得进日志。外部审计/幂等、普通用户权限矩阵、订单生命周期、实际转换、容量/接口和医院业务验收仍为上线条件。
