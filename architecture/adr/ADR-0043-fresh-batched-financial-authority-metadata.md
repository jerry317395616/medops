# ADR-0043 财务权限元数据的新读批量构造

## 背景与问题

真实恢复请求的共享 CI 剖析显示，74次权限刷新累计构造2258个原生 Meta，耗时31.562秒。各刷新点承担事务内撤权及字段/范围复核，不能直接移除或复用旧允许结果。隔离实验40820688375在29个模型上验证新读原始配置后调用原生 Meta 处理，完整字典零差异，SQL342降至174，三次中位构造耗时0.255582降至0.153388秒。自身事务的字段/角色元数据变化及回滚也可见。该实验尚不证明财务权限矩阵、实际接口或医院性能。

## 决策驱动因素

减少每个模型重复读取 DocType/五个子表的开销；保留全部核验点、当前主事务和未提交变化的可见性；继续使用原生字段、Property Setter、Custom Field 和 Custom DocPerm 处理；不修改用户 fork 的框架源码或增加权限。

## 备选方案

1. 跨检查点缓存元数据或允许判断：拒绝，会引入缓存绑定及撤权时效问题。
2. 使用原生 Meta(Document) 或 get_docs 后克隆：实验中29个模型不等价，丢失/增加属性且改变 DocField.show_preview_popup，拒绝。
3. 在每个现有检查点新读一批原始配置，并使用已锁定原生 Meta 的同等初始状态和处理过程：采用，未知构造方式回退原生逐项新读。

## 决策

只在 MedOps 内新增私有构造器，将同批 DocType 与原生定义的 fields、permissions、actions、links、states 子表分别合并读取。所有读取都使用当前 frappe.db，不另开快照连接、不提交、不复用前次配置。原始子行保留完整数据、父属和顺序，随后逐个构造实际原生 Meta，调用原生 process，并按原生 get_meta 的方式发布元数据。角色、User Permission、会话、来源、范围及写后复核仍走原有代码；全部刷新调用点保留。逐批发现 Table/Table MultiSelect 子类型，全部类型合计仍最多256，超出失败。

构造方式依赖用户 fork 4880ad1 的具体实现。检查原生公开读取器身份、Meta 类及固定子表映射，并比较八个原生构造/处理函数的规范源码摘要。未知、被覆盖或无法检查的实现回退 frappe.get_meta(name, cached=False)，不绕过第三方读取器。代码兼容性可按函数及代码对象身份记忆；元数据、操作者、角色或权限允许结果不可据此缓存。

## 后果

稳定配置下可减少构造开销，同时保留每次新读与原生权限语义。代码版本变化可能回退原生较慢流程；版本更新必须重新对照与压测。批量读取不是元数据的原子全局快照，原先逐项新读也不提供该保证；不把此优化当作并发权限提交协议。部分元数据构造失败时外围事务仍完整失败，不能使用已构造的部分结果放行写入。

## 验证与退出条件

原生验证完整根/子图字典与原生一致且实际 SQL 减少，普通预算角色无 DocType 管理权限时仍一致；热元数据后当前事务撤销字段、角色配置及用户角色分配必须可见，回滚后恢复；读取器覆盖和源码不匹配必须回退新读，非法/缺失配置不能给出部分成功。保留现有实际财务写后撤角色、字段、组织范围和原生 User Permission 的整批回滚用例，并运行完整普通/Core CI与已提交探针。构造实验耗时不得冒充接口或医院容量，须另测实际请求。

## 迁移与回滚

无模型、索引、权限、数据或依赖迁移；已有关闭的财务入口不自动开启。回退仅将权限元数据刷新恢复原逐项新读，保留其余身份、权限、事务、来源、证据与财务事实。服务器维护期间不连接或部署，现场容量、接口及验收另行完成。

## 安全与合规

仅为原生元数据构造提供当前原始输入，不返回预算许可，不创建确认或自动承认人工操作。无公开 API、DocType 类覆盖、财务写入或外部系统调用；所有生态应用仍使用用户固定 fork。源码摘要不含业务数据或凭据。未知版本的回退不是关闭门禁，仍执行原生新读及原有全部授权复核。
