# ADR-0026 核心主数据的范围权限、字段读取及请求主体隔离

## 背景与问题

COD-030 报表预查复现了早期主数据服务的缺口：没有任何访问范围、也没有 Item 读取权限的数据责任人仍能列出质量规则、读取问题和创建规则。组织及编号的早期 API 也没有完整接入 COD-024 的范围框架。直接在这些路径上聚合会继承越权。

## 决策驱动因素

角色表示业务能力，不能代替法人、医院、科室范围。服务写入仍需保留受控控制器与标准事务；读取复制值或质量结论时必须检查真实来源及字段权限。旧幂等记录要保留，不能删除或重新执行已完成动作来修复隔离。

## 备选方案

1. 只在新报表里增加过滤：旧入口继续越权。
2. 自动给现有角色授予全院范围或给目标记录共享：扩大权限，掩盖缺口。
3. 统一真实服务授权，逐条安全查询，保守保护历史结论，并绑定幂等记录的原始主体。

## 决策

采用方案 3，插入 COD-201 作为 COD-030 的前置任务。核心主数据、组织、标准组织映射及医院编号服务同时执行当前角色、数据范围和适用的原生权限。服务维护的只读模型不以普通 DocPerm.write 代替领域动作授权；对应 read/create/write/submit 范围必须明确授予。组织版本的整树维护要求医院范围的节点能力，不能以局部科室授权替换全树。

主数据申请的复制值、外部映射的目标及质量结论必须满足真实来源的原生读取与字段级/遮罩权限。Item、Supplier 等共享标准表没有医院维度，由受控主数据记录提供医院边界，仍须有标准目标的原生权限。全局主数据域配置只由系统管理角色维护。

普通 SQL 列表无法核验每条复制值的来源字段，因此四种主数据模型的通用列表仅 Administrator 可用；其他用户通过受限查询入口逐条检查。内部 ContextVar 只在可信查询内启用经过审查的范围/归属 SQL，客户端不能设置。分页仅针对可见记录，不公布未授权记录的数量。

质量问题新增 evaluation_read_fields，只保存字段名。新评估累积所用字段，永不缩减；读取结论和累计次数时须能读取全部相关字段。旧记录不能根据当前可变规则猜测历史字段，迁移以冻结主数据策略的全部允许字段作为保守读取约束，业务值、时间与发现次数保持原样。

幂等服务核验标准 owner 与当前会话主体一致，不改变旧键或响应格式；原主体可继续重试，另一主体使用相同键得到冲突。所有范围与来源权限在读取幂等快照前重查。

领域服务在事务内返回结果前执行 `authorize_result`，同样检查已完成重试的当前结果可见性；结果字段变为私有时拒绝返回，首次写入一并回滚。质量调度为新执行使用主体限定键，原主体拥有的既有旧键继续重试，避免跨主体重放和并行争用；不同主体的独立调度各记录一次评估。

## 后果

没有范围或目标读取权限的旧账号将被拒绝。必须由管理员显式配置范围及必要的标准目标读取/共享和字段权限，不自动授予。授权用户可用受控查询页面进入原单据；通用列表限制不能冒充无业务数据。质量评估和排队使用当前授权，队列执行时再次检查。

## 验证与退出条件

真实无范围越权必须在修复前复现、修复后被拒绝；验证跨医院、科室、原生目标读取、字段级与遮罩、历史规则改版、撤权后重试、不同主体的幂等、组织整树、编号、调度与 HTTP 路径。保留既有有效业务闭环；完整质量及当前受保护 CI 通过后才推广隔离站点。

## 迁移与回滚

新增一个内部字段并保守补全旧质量问题的读取约束，保持记录数量、业务结论和时间不变；按标准控制器递增内部修订。重复迁移无变化。部署先备份并暂停本项目任务；回退应用代码时保留字段及幂等数据，不能用回滚重新开放已确认的越权入口。

## 安全与合规

只记录授权事件、数量和摘要，不记录来源值、申请明细或凭据。不修改上游应用产品源码，不写会计或库存台账。医院容量、真实接口、UAT 及全 HRP 业务覆盖仍需后续验证；本安全修复不构成整体上线验收。
