# ADR-0050 私有采购承诺原子转换与受审计幂等回执

## 背景与问题

确认预览已经能通过标准控制器保存，但没有正式决定、承诺事件或受审计幂等服务。只保存决定再单独修改预算，可能留下孤立授权、重复转换或部分写入。已有确认不能赋予通用 SDK 写权限，摘要链也不证明真实人工操作。

## 决策驱动因素

标准控制器、共同来源与预算锁、独立确认、严格人工确认值、精确金额、完整混合历史、全局采购额度、整笔回滚、重试安全与凭证隐私。

## 备选方案

1. 直接更新冻结预占根的余额或先写决定后异步补事件：破坏不可变事实与原子性，拒绝。
2. 在普通权限打开后允许用户自行创建决定或事件：缺少精确来源、上下文和整体额度检查，拒绝。
3. 在既有完整准备状态与一个私有事务上下文中，通过标准控制器依次追加精确决定与事件，并重新核对实际保存的完整历史：采用。

## 决策

新增私有 PrepareReservationCommitment 和 PostReservationCommitment 域服务，复用统一认证、角色、审计、关联标识、加密幂等结果与保存点处理。输入只允许规范的预占、原生采购父/行、金额、理由，或确认标识、隐私凭证和严格 True；不接受客户端快照、预算集合或来源摘要。理由与凭证只以摘要参与请求指纹，原始凭证不进入诊断或明文回执表。

转换同时要求原有确认开关及新增 medops_internal_commitment_write_enabled 严格为 True，默认缺省关闭。先在干净拥有的事务内执行完整原生来源/预算闭包、当前权限、独立历史、当前前序与全局采购额度核查，重新读取已保存确认并校验其所有者、用户、会话、凭证、来源版本和五分钟窗口。确认与当前意图不同则拒绝，不能延长旧确认期限或复用被消费的前序。

私有上下文只准一个固定文档对象追加一条精确 Decision，之后另一个固定文档对象追加对应 Commit 事件。每个控制器阶段检查用户/会话、当前来源/组织/字段权限、凭证有效期和事务见证；任一预算初始写入、释放、确认或承诺上下文不得相互嵌套。标准 SDK、配置开关或空权限模型本身不能获得写入许可。

退出上下文前必须重新读取两条实际保存的完整行，并验证所有者、规范列、独立授权和完整事件链。重新枚举全预算位置，必须仅选定预占发生预期转换，其余位置和来源集合不变；重新核验全部独立采购分配，必须恰好新增一项决定，原集合摘要不变，精确总额与剩余额度只变化本次金额并仍满足当前采购上限。冻结根不更新。任一失败使事务围栏失效；服务和控制器不自行提交事务，调用者须完整回滚。

预览重放要求当前意图仍相同且凭证尚有效。已过账回执重放重新取得完整原生锁与当前权限、核查全部历史和全局分配，以及实际保存的决定和事件；凭证按原决定发生时刻验证，超过五分钟也只能返回原回执，不能追加新事件。完整转换后没有剩余预占时也必须能够核查旧回执，不应构造新的正金额意图作为读取前提。

## 后果

不新增表、字段、索引或权限；既有私有证据控制器增加严格受控的决定路径，事件控制器增加承诺分派。现有额度检查分离为通用完整采购分配核验与新增意图核验，以供写后及回执读取复用。事件上限只允许读取最后一条合法事件，不允许越界追加。完整核查有额外成本，医院容量尚未验证。

当前采购父单和行的修改时间不得早于其任一独立已承诺快照；经济事实相同也不能将时间倒退当作正常进度。当前仍无新的外部 API 或人工界面。其他原生采购写入口与生命周期共同围栏、Actual/承诺释放协议、非管理员权限矩阵、真实人工 HTTP、跨进程承诺竞争和医院验收须继续完成，不能据内部原子转换宣称 HRP 可上线。

## 验证与退出条件

纯逻辑验证请求精度、额外快照/预算输入拒绝、理由与凭证隐私、严格 True。保留全部既有额度、混合历史、原始/续期回执及权限回归。扩展限定空白 CI 站点的实际标准控制器探针，使用真实预算、预占、MR/PO 和私有基表，验证加密预览幂等、默认关闭、决定后/事件前失败、事件后过期整笔回滚、成功原子提交、过期后原回执重放，以及冻结根和 GL/SLE/预算下达不变；原始预占执行完整金额转换，续期场景执行部分转换。用户、会话、时钟和确认值为合成输入，不代表真实人已确认。普通/Core、本地全质量和精确源码完整回归均须验证，不以旧结果代替。

## 迁移与回滚

无结构迁移，仅常规元数据说明同步；用户服务器维护期间不连接或部署。回退先关闭两个新增阶段开关，保留所有确认、决定、事件、索引、幂等回执和兼容混合历史读取器。产生 Commit 后不得回退到只支持释放的读取器，不得删除或修改历史事实；后续经济撤销必须采用新的受控追加协议。

## 安全与合规

只使用用户 fork 的固定 Frappe、ERPNext、HRMS 和 Core，保持其源码不变。不直接写 GL Entry、Stock Ledger Entry、Bin 或已提交原生单据。没有事务内外部调用、自动人工确认或开放原始证据权限；新开关保持默认关闭。生产开通仍须完成公开边界、真实用户与医院策略验收。
