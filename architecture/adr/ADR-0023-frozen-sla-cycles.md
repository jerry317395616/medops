# ADR-0023 使用冻结日历的业务单据计时周期和标准待办升级

## 背景与问题

医院申请和审批需要响应、处理时限和超时升级。ERPNext 锁定版本的完整 SLA 控制器要求非提交类单据和特定 status 字段，不能直接套用具有提交生命周期和独立状态字段的 HRP 申请。

## 决策驱动因素

- 优先使用官方生态的标准配置及控制器；
- 暂停时间不计入时限，历史周期不随策略和节假日表变化；
- 重复调度不得重复派单，超时升级不得增加业务权限；
- 每次写入具有权限、幂等、修订、事务和脱敏审计。

## 备选方案

1. 修改 ERPNext SLA 产品控制器：违反仓库边界，升级成本高。
2. 把 HRP 请求伪装为 Issue：混淆申请事实与支持工单。
3. 通过受控 HRP 策略适配真实源单据，复用 ERPNext 工作时间格式、Holiday List 和 Frappe ToDo、Notification Log。

## 决策

采用方案 3。HRP SLA Policy 只接受声明式字段及有限列表，不执行表达式。源单据必须具有已审核的法人、医院、组织字段，以及 Select 状态和 Datetime 起算字段。

HRP SLA Escalation 表示一个源单据起算时间对应的计时周期。cycle_key 和 active_key 唯一约束分别阻止重复周期和同单据多个活动周期。新周期冻结策略、修订和日历，采用有界工作时间适配器；不调用 ERPNext 会读取实时节假日且缺少循环上限的完整截止计算器。

策略按精确组织、最近祖先、医院范围选择，再比较优先级；同等优先级歧义拒绝。祖先和候选数量均有上限，数据库先按组织筛选。旧周期保持快照，新策略只用于新周期，停止后不重开同一起算时间。

每次调度先锁源单据，再锁计时周期；通过幂等领域服务运行。升级只派发已到期的最高层级，跳过过时中间层级，保留 Version 记录。每个周期最多两个当前待办。ToDo 由标准文档控制器创建和关闭，预先检查用户启用状态、源 DocPerm 和组织范围，不使用会自动共享的 assign_to.add。通知只发站内 Alert，不发送业务邮件。

## 后果

本能力不批准、不付款、不记账，也不改变源单据的状态。关闭标准待办不等于业务响应或完成；响应由受控确认接口或源服务时间字段记录。策略停用仅停止新周期，已有周期继续使用冻结快照；管理员可带理由停止已有周期。周期不提供原地换绑策略，需由业务产生新的起算时间。

## 验证与退出条件

覆盖日历边界、节假日、暂停恢复、精度、策略修订、重复执行、唯一约束、实际源钩子、越权、收件人失效、错误退避、待办防篡改和 HTTP。全量 Frappe 测试、重复迁移、仓库检查及受保护 CI 全部通过后方可合并。

## 迁移与回滚

新增两个运行 DocType、三个复合索引及工作台入口，迁移不创建业务策略或扫描历史业务单据。部署前备份隔离站点。回滚代码保留周期和待办；紧急停止调度并通过受控接口停止活动周期，不删除历史记录。只重启本项目隔离环境的进程。

## 安全与合规

管理员维护策略及停止、立即检查周期。确认响应仅限责任人、当前升级接收人或管理员，且仍需源单据权限。普通读接口逐条检查源单据权限；通用 DocType 列表只向管理员开放周期。审计只记录状态、计数、修订和摘要，不记录单据标识、地址或原因正文。未获得医院规模及脱敏接口资料，容量与真实业务验收仍是上线门槛。
