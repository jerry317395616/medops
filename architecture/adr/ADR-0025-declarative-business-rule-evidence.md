# ADR-0025 声明式业务约束实时校验与只追加历史证据

## 背景与问题

医院资源业务需要跨字段、日期、金额和明细行约束。现有数据质量规则侧重主数据字段检查，审批、职责分离及 SLA 各有独立职责。未来预算、采购等模块需要统一约束服务，不能通过历史验证结果绕过当前权限或规则。

## 决策驱动因素

优先复用 Frappe 元数据、字段权限、标准文档生命周期和现有组织、幂等、审计服务。保持声明式、有界计算，保护遮罩及高权限字段，不在日志中复制敏感业务原文。

## 备选方案

1. 直接使用 Workflow、Server Script 或任意 Python 条件：配置灵活，但难以限定执行范围和推断泄露。
2. 仅扩展单字段数据质量检查：不能充分表达跨字段或明细约束。
3. 有界 JSON 条件树及类型化元数据契约，实时判断，单独保存历史证据。

## 决策

采用方案 3。HRP Business Rule 声明真实单据类型、动作、组织范围、有效期、适用条件和业务约束；Block 阻止动作，Warn 保留警示。支持 all/any、字段及字段间比较、集合比较、非空检查和非空明细 all/any；禁止表达式、脚本、自定义正则和嵌套明细。金额使用 Decimal，不执行货币换算；不同货币元数据字段不隐式比较。

字段类型、选项、权限级别和遮罩状态进入契约及摘要。运行时漂移默认拒绝，管理员以修订重新确认。读取真实单据时同时检查 DocPerm、组织范围、字段读取和遮罩权限，避免通过规则结果推断不可见值。组织和日期源于实际单据，候选规则先按组织及有效期过滤，全部适用约束累积执行。

实时 evaluate 是只读查询，不缓存授权判断。record 是幂等的历史证据写入，必须绑定源版本和实时判断摘要，只返回记录标识和历史标志，不返回可重放 allowed。HRP Rule Execution Log 只追加，保存摘要、元数据字段引用及规则结果，不保存源值；读取记录时重新检查源及字段权限。通用列表不能应用动态字段权限，普通用户通过范围接口访问。

写操作先锁真实源，再对医院主数据取得共享配置锁；配置写入取得医院排他锁，再锁规则修订。这样阻止在校验和业务提交之间更换规则，同时允许同院不同源并发校验。数据库冲突仍由 ADR-0024 的外层事务重试。

主数据申请提交是首个业务接入：在原有角色、范围、版本、提案校验基础上执行规则。有匹配配置则必须通过；全部条件不适用也不算通过。未配置时保持原有受控流程，明确记录为未配置，不声称已由规则授权。未来要求强制策略的财务模块必须使用 required=True。

## 后果

规则不批准、付款、记账或直接改写 ERPNext/HRMS。成功业务校验的证据与业务事务一起提交；失败动作回滚其数据库证据，拒绝事件仍进入脱敏运行审计。需要持久保留拒绝结果时可显式 record，不把失败事务的回滚记录冒充已落库。主数据提交状态检查移到幂等预留之后，允许原键重试返回已完成动作结果。

## 验证与退出条件

类型、日期、Decimal、条件组合、明细、复杂度上限、元数据漂移、组织及字段越权、实时判断不重放、历史证据只追加、源或策略变动拒绝快照、真实主数据提交和回滚、HTTP 与并发幂等均需证据；完成全部必需 CI 后正常合并。

## 迁移与回滚

新增两个运行模型、三个索引及入口，无业务策略种子或历史单据重算。先备份隔离站点，再重复迁移。回退代码前暂停本项目任务并清点队列，保留规则和证据表；已应用的业务动作仍按标准控制器取消/更正，不删除历史记录。

## 安全与合规

管理员维护策略，审计员只读配置；试算、记录和日志读取必须具备真实源访问及字段权限。运行审计只记录策略摘要、数量与结果。医院规模、真实接口、UAT 和完整业务闭环仍是总体上线门槛，本任务不构成三甲生产验收。
