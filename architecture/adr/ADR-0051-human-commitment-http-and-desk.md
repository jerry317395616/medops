# ADR-0051 采购承诺人工核对接口与原生工作台

## 背景与问题

私有采购承诺域服务已经验证原始预占全额转换、回滚与回执重放，仍缺人工可操作的入口。客户端不能决定预算范围、来源快照或承诺额度，不能把预览成功当作已承诺。金额、订单、组织、理由和有效期须供人明确核对，网络结果不明时也不能换键追加。

## 决策驱动因素

复用 Frappe 原生页面和请求认证、既有受审计幂等服务、严格默认关闭、当前原生字段/组织权限、完整人工核对、不丢失未知命令、真实 Cookie 与浏览器验收。

## 备选方案

1. 开放私有证据 DocType 或由浏览器构造快照、预算集合与决定：拒绝，无法证明原生事实及人工授权。
2. 独立建设另一套前端、会话、幂等与审批服务：维护成本高且容易与既有预占流程分离，拒绝。
3. 扩展现有采购预算预占 Page、命令日志和 POST 边界，仅调用既有私有域服务：采用。

## 决策

reservation_operations 新增 commitment_orders、prepare_commitment 和 post_commitment。沿用已认证 System User 的原生网页会话、POST、CSRF、当前管理角色、未知字段拒绝、总开关及拥有的干净 READ COMMITTED 事务；拒绝访客、GET、Authorization 头和后台请求。总开关及各私有承诺开关须严格为 True，缺省关闭，不随安装或迁移启用。

订单选择器接收一个规范预占引用和先前完整核查返回的当前来源摘要。该摘要只是版本标记，不能提供权限或财务额度。读取原始独立记录并检查当前根写范围后，在没有预算围栏的独立事务里调用既有原生关联订单检查器，先锁申请与全部订单父单，再核验当前来源、原生字段/范围、链接、经济事实和有界集合。只返回当前可读订单行的有限业务信息及原生表格行序，不能返回可用预算或私人证据。再次核查原始记录、当前身份和角色。

预览和转换只接受既有规范命令：预占、订单、原生子行、精确字符串金额与理由，或确认引用、凭证和严格 True。服务仍独立完成完整范围、当前来源/历史/额度与人工确认校验。预览通过后，由同一当前准备状态生成受限核对信息，包含实际订单行、供应商、原始来源、预算键、可读名称与代码、精确金额、未结预占、订单未分配金额、成本中心、费用科目、理由、执行人和到期时间。读取名称仍逐字段鉴权；完成预览后任一核对字段失权也必须由最外层 HTTP 回滚整个确认及幂等结果。

post_commitment 加入既有认证前凭证保护列表，覆盖 JSON、表单、cmd、RPC 多版本和兼容后缀。凭证不进入诊断、DOM、浏览器持久化存储或可枚举页面状态。域服务负责审计与加密幂等，Frappe 负责最终提交或回滚。确认只表示预览，只有 reservation_committed 响应才表示实际决定与事件已原子保存。

Page 从完整核验的预占选择关联订单，填写金额与理由，再展示独立核对窗口。窗口默认不勾选确认，信息缺失或订单/根不匹配时不能进入确认步骤；人工明确勾选后才发送转换命令。承诺不调用首笔预占确认或续期路径。命令日志为这两个动作增加独立方法与影响校验；未知财务结果只允许保留原字节、原会话与原幂等键重试，输入变化或关闭页面不能悄悄丢弃未知操作。

当前位置增加累计承诺、未结承诺和实际使用；released 同时包括释放和承诺转换，因此显示为“累计转出预占”，避免误认为所有转出都恢复了预算。浏览器不以浮点数重新计算金额。机构预算名称与代码、原生订单编号和明细行序用于核对，内部摘要不作用户操作字段。

## 后果

没有新表、字段、索引、角色或标准证据权限；修改现有 Page、请求保护、API 与前端命令日志。CI 仅在现有精确命名的空白一次性站点开启承诺开关，默认关闭用例显式覆盖关闭值；测试角色和权限变更不能进入安装流程。原生 Cookie 测试不能代替视觉和真实人业务验收；模拟控件测试也不能代替真实 Desk。

## 验证与退出条件

保留原有全部 19 项前端回归，新增订单选择、独立未勾选窗口、不完整核对拒绝、明确确认和未知命令同键重试，合计 25 项。新增两项纯解析测试；扩展所有既有 HTTP 关闭/访客/GET/令牌/后台/错误参数/凭证诊断测试，不能漏掉新方法。

在精确隔离 CI 站点，以实际预算、原生申请/订单、独立证据、普通预算经理及真实 Cookie 执行完整流程，验证来源摘要变更拒绝、预览权限失败后整笔 HTTP 回滚、组织范围撤销、原生订单字段失权、严格确认、实际 Commit、精确投影与加密幂等/过期后原回执重放。测试角色仅补充原生采购/库存读取能力，不授予私有证据访问。普通/Core、全量回归和实际 Chromium/Desk（含截图检查）仍须完成。没有真实人工、医院容量、接口、生命周期和实际支出验收时不能宣布 HRP 上线。

## 迁移与回滚

只需后续正常应用代码/前端资源发布，无结构迁移。用户服务器维护期间不连接或部署。回退前关闭总入口及承诺开关，保留全部确认、决定、事件、加密回执和兼容混合历史读取器；未知请求须核实既有结果，不能通过换键或删证据解决。允许回退界面而保持财务读取兼容，不回退到只支持释放的旧读取器。

## 安全与合规

复用用户 fork 的固定 Frappe/ERPNext/HRMS/Core 和原生控制器，不修改其源码；没有直接 GL/SLE/Bin 写入、服务内提交或事务内外部调用。预算/组织/字段权限逐次核验，外部调用不能选择服务类、表或 SQL。现场政策、真实人、非合作采购写入口、承诺竞争、承诺释放、Actual、备份恢复和全院容量仍是上线条件。
