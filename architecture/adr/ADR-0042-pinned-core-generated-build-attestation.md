# ADR-0042 锁定 Core 源码与生成资源的独立完整性证明

## 背景与问题

新 Bench 必须构建全部应用，才能提供原生登录与 Desk 所需的资源。完整 CI 40719053510 的 Core 业务测试通过，但末尾工作树门禁失败：用户 fork 的固定 Core 提交 `8c697bafd30aebd418aee18f618b287bbab557f3` 中，Vite 配置会清理并重新生成 `ione_core/public/mobile`，再复制入口至 `ione_core/www/ione-mobile.html`。这些输出已被上游纳入 Git；重新构建会替换带内容哈希的文件。该失败不能冒充业务通过后的完整 CI 成功。

## 决策驱动因素

保留全部应用构建、固定 fork 和源码零改动约束；允许配置明确声明的生成输出；测试后必须核验输出仍是构建结束时的版本，不能在最后重置工作树掩盖变化。

## 备选方案

1. 跳过 Core 或框架资源构建：会缺少实际使用所需资源，拒绝。
2. 忽略 Core 工作树或最后重置输出：可能掩盖源码或测试改动，拒绝。
3. 对锁定源码、有限生成路径及构建后完整清单分别证明：采用，不修改 Core 源码或配置。

## 决策

仅自有 bootstrap/CI 增加标准库校验脚本。构建前要求 Core 固定提交且工作树、索引洁净。构建后仍要求固定提交及洁净索引；对比 HEAD 的变化只可出现在 mobile 的 index.html、manifest.webmanifest、service-worker.js、assets 下单层带八位内容标识的 JS/CSS，以及指定 www 入口。其他源码、配置、依赖清单、未跟踪代码变化一律失败。复制的两个公共文件必须与 frontend/public 对应固定源码相同，www 入口必须与非空 mobile 入口逐字节一致，并有 JS 输出。

生成目录全量扫描，包括 Git 忽略的文件；不符合有限路径的文件和符号链接失败。记录所有受版本管理及非忽略的未跟踪文件、全部生成文件的 SHA256 与执行位，包含旧资源删除后的实际清单。证明文件必须位于 Core 检出目录之外且不得覆盖。CI 父进程在业务测试前保留证明摘要；最后要求原摘要、提交、源码约束和全文件清单一致。源码或资源在测试中增加、删除、改内容、改执行位，或证明被替换，均失败。其他四个应用继续要求原有 Git 洁净门禁。

## 后果

构建产生的 Git 差异仍保留，可供审计；只有明确定义的产物变化可以通过。该证明不认证第三方构建工具，也不替代供应链检查、浏览器功能、性能或医院验收。Core 提交或输出布局改变时必须重新审查边界，不能扩为任意目录豁免。

## 验证与退出条件

临时 Git 仓库执行真实文件新增/删除、源码与未跟踪代码篡改、索引变化、错误提交、入口/公共文件不一致、构建后资源变化和证明替换反例。Linux CI 额外验证实际符号链接和执行位；本地验证符号链接拒绝分支。完整普通/Core CI 必须重新运行，原失败保留。该决策仅处理构建完整性，不声明原生 Desk 或上线就绪。

## 迁移与回滚

无 DocType、权限、依赖或业务数据迁移，不连接维护中的用户服务器。回退校验脚本与调用可恢复原严格工作树失败行为；不能借回退跳过 Required、Core 或完整资源构建，也不能重置上游源文件制造成功。

## 安全与合规

仅从用户 fork 的固定提交读取源码。证明只有路径、内容摘要、执行位及提交，无业务数据或凭据；无公共接口、财务写入和授权改变。所有历史事实与既有财务权限检查保持原样。
