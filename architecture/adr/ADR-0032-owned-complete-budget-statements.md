# ADR-0032 原始单位完整账簿与自有只读连接

## 背景与问题

科室需要读取自己参与跨科室汇总形成的下达分录。仅从可见行求和会将缺行或撤权伪装成完整账簿；公开父批次及其摘要可能泄露其他科室。默认事务及共享权限缓存还可能隐藏查询期间的撤权。查询入口不能结束调用方尚未提交的事务。

## 决策驱动因素

完整合计、原始单位边界、当前角色与字段授权、金额精度、无隐含授权，以及复用固定版本的 Frappe。

## 备选方案

1. 原生列表过滤后累计：实现简单，但不能证明缺行和完整性，拒绝。
2. 强制用户拥有全部父批次来源：权限实现直接，但科室无法读取自身分录，拒绝。
3. 私有完整批次校验与原始单位公开投影分离，由自有只读连接核验整个账簿，选用。

## 决策

外层 API 保存实际调用方连接及会话/权限缓存对象，新建 READ COMMITTED、数据库强制 READ ONLY 连接。内存能力绑定连接和当前用户，服务仅在该边界内执行；结束时回滚并关闭新连接，恢复原对象，不提交或回滚调用方事务。复用 ADR-0031 的当前角色、原生 User Permission 和元数据刷新。

请求必须明确原始单位、年度、币种；不自动扩展下级单位。日期只能在年度内。先证明上下文及当前权限，再私有枚举相同组织版本、年度、币种、截至日期内的已过账凭证，不按父批次单位或可见分录筛选。涉及当前单位的批次逐字段与冻结事实及完整反向生成器核对；所有本单位来源复用完整已批准科室申报权限链。最后与本单位物理分录标识集合比对。缺失、孤立、错误维度及任何来源拒绝均不返回部分合计。

完整账簿核验后才分页，每页最多50行；后续页绑定完整账簿摘要。返回前刷新当前授权，重新核验上下文及全部本单位来源，同时比对权限元数据/授权事实私有摘要及凭证、分录集合，排除查询期间缓存成功掩盖撤权。私有摘要及其他科室批次信息不进入公开结果、账簿摘要或日志。最终验权是该次读取的授权截止点，后续读取重新核验。

账簿上限50000条本单位分录、1000批凭证及1000000条私有来源证明工作量；权限事实上限50000行。超过边界拒绝整次查询，无静默截断。上限是安全界限，尚无大型三甲容量承诺。

公开单笔接口只返回固定字段白名单。原生 Ledger 文档、列表和链接标题继续保持既有拒绝策略，避免通用序列化公开私有批次字段。内部原生基础检查的内存哨兵只移除自有拒绝钩子，仍保留 Frappe 角色、分享、User Permission、当前字段与范围检查。

金额用 Decimal 独立精度上下文累计并返回十进制字符串。XLSX完整导出复用 Frappe make_xlsx 与现有 XlsxWriter，所有数据为字面文本，禁用公式、URL、数字推断；导出再次要求全部来源及范围的 export 权限，并绑定查询摘要。

同一自有只读连接复用于下达操作台的单笔凭证、凭证目录和待下达来源。目录要求明确法人、医院与年度，原生范围查询后逐项核验完整来源；最多1000候选、每页50项，超界拒绝。公开摘要仅绑定可见投影、顺序及筛选，后续页须绑定该摘要；结果阶段重新查询、核验全部投影及当前授权指纹。目录不提供隐藏候选计数，也不构成完整账簿合计。私有已占用来源查询只排除已有Release意图，不返回已有凭证标识或授予读取能力。候选拒绝的响应和消息状态在局部隔离，不能污染成功目录；最终被请求的凭证或整体结果拒绝仍返回标准错误。

完整来源重复核验在252个候选的目录剖析中耗时254.195秒。相同已完成结果仅可在当前自有只读连接、当前执行人、同一同步access_graph阶段内复用；该能力缺失、连接/身份改变、锁定写入或离开图后均重新读取，异常不缓存。凭证读取按原语义先重载已存凭证；审批、申报、计划及版本权限键绑定传入Doc完整字段的SHA256、显式用户与权限类型，拒绝同名篡改文档或其他用户复用。私有来源完整性缓存不授予可见性。首次收集和最终授权使用独立图，最终角色/字段/分享/范围指纹及全部可见投影核验保持不变，不跨请求或授权刷新保留成功。

原生Link字段的异步校验可能在发起查询后对同一值再次触发onchange。页面按规范筛选签名仅在实际值变化时作废结果及在途请求；同值回调保留当前查询。分页仍使用完整账簿摘要，任何真实筛选变化继续递增请求标识、清空结果并禁用导出，不保留跨筛选的数据。

## 后果

增加一次独立连接及完整来源证明成本。复杂查询暂不提供任意筛选和父组织汇总；业务使用者不会得到不完整的伪账簿。无需修改上游代码、引入依赖或新增财务模型。原生主数据可能没有默认export授权，HRP台账export不足以授予全部来源导出；由医院管理员显式配置，安装不补造授权。文件正向验收使用已有完整权限身份，不证明普通科室生产权限配置已完成。

## 验证与退出条件

纯逻辑验证精确合计、分页摘要、边界、日期及不可变投影。隔离 MariaDB 验证跨科室拒绝、缺行/错额、完整反向、实际HTTP/XLSX、查询中撤销分享/字段/User Permission、旧Redis、调用方未提交写入与会话保留，以及数据库只读强制。页面须独立验收。容量、接口及真实医院UAT另行验证；若需持久快照或跨年度账簿，应重新评审。

## 迁移与回滚

迁移导入自有 Page 与工作台入口，不改存量财务行或用户授权。重复迁移须保持预算行和用户角色不变。回滚代码与入口即可，保留所有既有分录及决定证据，不删除表或重算金额。

## 安全与合规

查询不授予角色、范围或分享。不将临床资料、财务金额、私有来源摘要、令牌及会话数据写入审计；审计只记录操作与计数。授权事实摘要仅存在请求内存。无外部数据发送或官方 GitHub 连接。

### 单阶段授权事实复用及被拒绝的文档缓存

相同459候选、相同候选/列表/分页摘要下，原始1627858耗时77.527秒、88042次SQL；33709af文档快照原型耗时80.258秒、84125次SQL，没有实际提速，因此撤掉七类完整文档字典和深拷贝缓存，不保留该复杂度。252候选43.574秒的旧结果来自不同数据集，不能用来证明这次改动的收益。

实际SQL归因发现范围授权14124次、流程定义及子表10539次重复查询。共享纯Python查询适配器只在物理READ COMMITTED/READ ONLY连接建立后注入现有单阶段缓存。范围服务仍使用原有SQL和冻结ScopeGrant元组，键含执行人、文档类型、动作及站点当前日期；文档维度匹配逐次执行，其他用户及无适配器的查询不复用。通用范围模块不依赖预算模块。流程校验只复用成功布尔结果，不缓存或公开可变Workflow文档；审批写入能力存在时继续原生读取和加锁。

实际连接、执行人和access_graph阶段的边界继续由现有受控能力验证；显式刷新执行人会清空仍打开的图，首次及最终授权继续独立取数。没有跨请求缓存、表/字段/接口/迁移或用户授权变化。新增并发上下文隔离、异常退出恢复，以及真实SQL阶段边界/日期/动作/撤权与外层图显式刷新用例。相同459候选复验及原生回归完成前，不宣称优化通过或达到医院容量。
