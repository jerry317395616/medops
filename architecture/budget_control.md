# 预算并发控制的开发边界

此文档记录 COD-034 的开发进展，不构成可开放的预占接口。目前候选代码已将 [ADR-0035](adr/ADR-0035-budget-overlap-scope-guards.md) 的共同预算围栏接入人工授权的下达和完整冲销后台任务。隔离 Frappe/MariaDB 定向测试已验证后台过账、部分锁竞争与回滚；完整 CI、真实医院数据、容量和部署验收仍未完成。预占事件写入、额度计算和其他使用路径仍未开放，所有参与预算使用的写入路径必须统一围栏并禁止混版，不能据此认为已经具备上线条件。下文按开发顺序保留阶段性说明，其中“尚未接入”“尚未运行”等表述仅表示相应段落记录时的状态；以本文首段、末尾更新和验证报告为当前状态。

BR-BUD-002 的八个维度必须全部显式提供，空项目以 `null` 表示；期间维度使用实际起止日期，不使用各版本可能不同的期间序号。锁为同一预算范围的所有年度和期间提供共同围栏；已接入的下达与冲销候选会检查历史期间重叠，规则未明确时不同日期范围若存在重叠须失败关闭。期间的有效性、各维度之间的关系及医院数据范围须在服务中按当前来源核验。纯函数只规范化字符串而不解析数据库身份；未来服务须先取得每个已授权来源的实际 `name`，确保数据库视为同一记录的不同输入写法得到同一锁，不能自行假设 Unicode 大小写折叠等同数据库排序规则。不同币种或不同捕获精度不得仅因键相同就合并，必须在锁内检测并明确拒绝。

`resolve_budget_control_key` 为固定的公司、医院、组织、年度、科目、资金来源和可选项目调用现有 `native_document` 读取权限检查，并采用实际文档名生成规范键；不允许调用者提供 DocType。它不检查维度之间的归属与有效期、不授予写权限、不固定来源或取得预算锁，后续写服务必须在锁内重新检查并处理来源变更。当前仅新增模拟来源及标准读取器数据库别名测试，尚未在真实 Frappe 中运行，也没有接入业务入口。

批量下达或冲销键可通过 `resolve_release_control_keys` 将事实键交给名称解析器，再按实际名称去重；来源文档缓存仅限单次调用，同一调用中共享引用复用一次读取，不跨请求缓存权限。此组合不取得锁、证明来源间关系或授权写入，锁内必须重新读取完整来源和当前权限；模拟测试尚未在 Frappe 中运行。

`prepare_release_guards` 候选在锁前解析下达或完整冲销键，取得围栏后使用全新调用再次解析并核对名称；重读失败、变更、超时或死锁时将连接标记置为失效并保留原异常。失效标记只在内存中设置，不做额外 SQL，保存点回滚不能清除；显式检查和正常提交前检查拒绝失效状态，完整回滚后清理。它仍未验证持久化批次完整性、组织关系、写权限、币种和已发生事件，也没有接入下达、冲销或预占写入口；新增真实数据库测试使用模拟来源，尚未运行。

`prepare_persisted_release_guards` 候选按现有来源→凭证顺序锁定已授权下达单，验证预期修订、刷新当前操作者及来源授权，冲销时核验原始已过账批次完整性；取得预算围栏后再刷新授权、重读凭证并复核冲销原批次。任何后续异常使围栏失效。它未取得执行租约、不执行记账，也不枚举所有相关预占/调整/实际事件或证明额度，未来所有写入口仍须统一锁序并完成额外验证。新增原生下达、权限撤销和冲销用例尚未运行。

现有纯校验 `require_nonoverlapping_budget_periods` 将已规范化的完整现有及拟写键按共同范围分组，按含首尾的日期比较，拒绝不同键重叠；完全相同的键去重，不同年度使用相同日期也按歧义拒绝。该方法限定输入不超过 1000 项，并复用锁范围的同一组维度；超过界限必须失败，不能截断。它不查询记录、不证明调用方取得全部相关键或持有共同锁，也没有接入业务服务。

下达与整批冲销可通过纯函数 `budget_keys_for_release_batch` 从已封存来源派生同一组原始科室和期间键。冲销必须提供并匹配原下达事实；超出 1000 条来源行直接拒绝，不能截断。它不核验数据库完整批次、当前名称和权限，也不获取锁或进行记账，因此不得直接作为写入许可。

BR-BUD-001 的七项金额须由事务内完整、已去重、来源和链路经过验证的事件推导；`approved` 分量只能来自已执行的预算下达事实，不能把尚未下达的审批作为额度。纯函数既不证明这些条件，也不生成资金事实。金额使用现有 15 位整数、0–9 位小数的精确协议；负余额仍可用于问题核对，任何调用方都不能把单独的比较结果当作预占许可。分量 `released` 不自动证明其来源或可重复使用，释放与预占、承诺、实际的状态转换和反向关系须由后续 COD-035 设计并验证。

事务实现须先收集全部预算键并一次性按全局顺序获得范围及期间锁，再刷新权限及源事实，随后检查额度并追加不可变证据，最后在相同事务中核验结果授权。锁原型在数据库连接上登记单次调用标记，完整提交或回滚后由原生回调清除；保存点回滚不会执行回调，因此即使保存点内写入被撤销，后续再次请求锁也会拒绝，直到完整事务结束。候选实现额外写入仅含随机名称的 InnoDB 事务见证行；回滚到取锁之前的保存点会撤销见证，显式 `assert_budget_guards` 与正常 Frappe 提交前检查应拒绝继续，回滚到取锁之后的保存点则保留见证。正常提交前只删除该见证，完整回滚由数据库撤销；本地独立 MariaDB 已验证基础事务现象，Frappe 回调和真实锁测试尚未运行。该标记不能阻止其他代码绕过 Frappe 事务管理器直接提交或绕过锁，所有业务写入口仍须受控；真实数据库与回调测试尚未运行。多键操作须固定顺序以减少死锁；数据库508/死锁信号必须保留给外层整笔重试。下达、原批次冲销和额度使用均须纳入同一围栏，不能只锁新预占而让旧冲销绕过它；未识别的后续事件必须失败关闭。未完成上述工作前，净下达额不等于可用余额。

接入现有领域服务时须处理具体的保存点边界：`DomainService.execute` 在命令保存点之后调用 `perform`；现在普通业务异常进入 `_rollback` 时若连接持有预算锁标记，则完整回滚当前事务，否则仍按原行为回滚服务保存点。该变更会撤销同一事务中服务之前的其他未提交写入，调用方必须将该错误视为整笔失败；数据库死锁和超时仍原样交外层回滚重试。这一分支新增真实数据库测试但尚未运行。此保护只覆盖经过 `DomainService._rollback` 的普通异常；业务写入必须显式校验见证并在锁内重读所有事实；直接或嵌套提交、手动修改回调队列以及绕过锁检查不受完整保护，外层遇到提交失败必须完整回滚并停止。必须在真实 HTTP 请求、后台任务和嵌套服务中验证异常不会被吞掉，或者设计经测试的事务失效机制，确保这些路径不得提交预算业务写入。不能简单依赖 `before_commit` 回调：锁定框架的 `Database.commit` 在执行 `before_commit` 前重置回滚回调，若该回调抛错，还必须证明后续完整回滚能清除连接状态。未经证明前不得把原型接入写服务。

现有下达执行的业务入口是 `ExecuteBudgetRelease.perform`：先由 `lock_release_source` 锁定审批来源及下达单（冲销时还锁原单），再锁 Outbox 消息，验证授权后由 `write_complete_batch` 追加下达或冲销记录。未来预算控制须覆盖这条实际执行路径以及所有新增使用/释放路径；准备或确认下达单本身不是最终写账。插入预算锁之前须为所有写入口定义兼容的全局锁顺序，并测试跨下达、冲销和预占的竞争及死锁重试，避免只对预占加锁而保留冲销绕行。

见证使用同一站点 `tabSeries` 中独一随机行，不含预算维度或金额；正常提交前在同一事务删除，不应留下持久记录。若见证检查自身失败，候选回调重新注册提交检查及回滚清理，避免重试提交绕过它。框架会先清除回滚回调，再调用提交前回调；候选依照 [ADR-0036](adr/ADR-0036-budget-guard-callback-order.md) 先于普通回调恢复清理，再将最终见证检查移到普通回调及其新增回调之后。该方案依赖锁定框架的内部 deque，结构不符时拒绝取锁；早晚回调失败、重复提交与动态添加用例均待真实 Frappe 执行。直接或嵌套提交、手工队列操作、连接中断、权限与混版仍须单独验证，不能将该原型视作生产并发保证。

GitHub 40494066439 的 IONE Core 测试中，持锁方回滚后两个同范围等待进程竞争，`INSERT ... ON DUPLICATE KEY UPDATE` 的一个等待者抛出 `QueryDeadlockError`；同次另有诊断 MyISAM 清理失败。错误的具体数据库锁图未采集，不推断其死锁根因。测试进程现按最多四次整笔事务重试并模拟首轮死锁，先完整回滚再重新取锁；正式业务入口的重试和最终结果仍未实现、未经验证，不能把测试重试当成生产能力。

`guarded_release_inventory` 候选要求已持有完整键围栏及科室范围，按法人和医院枚举已过账下达凭证，以原始科室筛选后复核整批，将原始科室的全部物理预算台账分录与已验证分录集合比对，并检查当前读取权限、来源、科目引用和围栏。它不按年度、组织版本或币种过滤，超出上限或出现孤立、缺失分录失败关闭。此候选未接线、未经原生数据库测试；下达之外的事件没有纳入，现有写入也未全部遵守围栏，因此不能证明并发完整性、计算额度或授权任何记账。

`prepare_persisted_release_inventory` 在已授权下达单的现有来源复核和围栏后读取下达历史，拒绝同范围内不同且重叠的期间，并拒绝拟写预算键上的不同币种或精度；不同不重叠期间可独立使用币种。历史币种用原生读取器解析实际名称，授权刷新后重新读取。该内部组合不证明其他事件、可用额或统一写锁，不能用于授权记账，真实 Frappe 组合测试尚未运行。

`focused-budget.yml` 为指定隔离测试分支提供五项真实 Frappe 预算关键路径及两项事件存储检查，使用锁定的个人 GitHub fork 和独立站点，要求分别执行五项和两项且错误日志为零；脚本仅允许 GitHub Actions 临时目录。它不替代完整 Required、IONE Core、保护分支、压力或医院验收。

`replay_reservation_events` 是 COD-035 的无持久化前期契约：同一预占链按连续序号重放精确金额；预占转承诺及承诺转实际时，将转出金额计入 BR-BUD-001 的 `released` 抵消项，使每笔余额只占用一次。显式释放也计入该项，开放预占和开放承诺不得为负。`released` 在此表示公式抵消累计量，不能直接等同于业务取消金额。该契约不检索事件、不证明来源或数据库唯一性、不审批或占用额度；直接承诺、实际退款、实际医院策略、持久化及授权须后续设计实现。

新增 `HRP Budget Reservation Event` 空表模型，保存完整预算维度、捕获精度、预占序号、来源动作和事件摘要；事件键、预占序号键及来源动作键分别声明数据库唯一约束。当前无 DocPerm，控制器拒绝所有标准文档写入，任何业务入口均不能使用它创建事件。迁移将在站点创建空表；结构和唯一索引须在隔离 Frappe 站点及重复迁移中验证。未来授权写入须绑定来源事实、独立人工确认、同一预算围栏、幂等和完整链核验，并禁止新旧进程混写；不能直接写数据库绕过控制器。

预占事件来源身份由真实来源类型、名称、修订、明细、分摊及动作共同生成；来源动作键不包含目标预占，防止同一来源版本的相同明细、分摊和动作跨预占重复使用；不同来源修订是否代表新业务须由适配器核验。事件键与序号键由预占及连续序号派生，事件摘要覆盖预算维度、金额、币种精度、来源、操作者、发生时间、前序摘要及唯一键。明细、分摊和动作必须由受信来源适配器从已核验业务事实派生，不能信任外部自行提供的任意键；操作者与时间也必须由服务可信地产生；摘要不是数字签名，不替代数据库完整性、权限或审批。当前仅为未接线纯契约，表写入仍关闭，新增字段须隔离迁移验证。

`budget_reservation_storage` 提供事件证明与表行的无数据库往返转换，检查全部字段、数据库日期类型、来源动作键、事件摘要、前序链、记录数和最终摘要，并拒绝超过事件上限。要证明未漏行，记录数及最终摘要必须来自独立可信、持锁的预占聚合；当前尚无此聚合、来源权限检查或受权数据库读取器。该适配层不查询或保存事件，也不授予写入权限。

新增未接线的 ERPNext 物料申请来源读取候选：在 READ COMMITTED、非自动提交事务中检查当前用户及标准单据/字段权限，按原生文档锁定申请与子行，并核对医院组织、映射、成本中心和业务日期；用 MariaDB CAST 将存储的数量、单价、金额作为精确文本读取，避免锁定 Frappe 驱动将 DECIMAL 转为 float。来源快照包含文档、行、映射修订及所选字段摘要，但当前公司默认币种不证明历史币种，也不能证明来源已审批、全部关联事件、预算科目/资金来源、完整分摊或全局锁序。它不提供API、不写入预占或扣减预算；调用方在业务写入前仍须锁内重新校验授权、来源、预算围栏、幂等和额度，并处理ERPNext原生预算校验的协同。新增隔离 Frappe 测试待运行，不能据此声明上线。
