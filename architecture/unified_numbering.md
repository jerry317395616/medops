# 统一编号服务

## 能力边界

统一编号服务位于 `HRP Foundation`，只负责维护受控编号方案和分配不可重用的业务编号。它不创建采购
订单、预算、合同或财务凭证，也不修改 Frappe、ERPNext、Frappe HR 的控制器和台账。

## 编号方案

`HRP Numbering Scheme` 使用稳定大写编码作为名称。方案绑定法人、医院和可选组织单元，并具有启用
状态、有效期和乐观修订号。可配置内容包括：

- 模板：最多 120 个字符，只允许受控字面量和占位符；
- 重置周期：`Never`、`Yearly`、`Monthly` 或 `Daily`；
- 流水号位数：2 至 12；
- 起始序号：正整数且必须能放入配置位数；
- 维度键：从模板的 `{DIM:key}` 自动提取，不单独录入。

模板必须且只能包含一个 `{SEQ}`。支持的日期占位符为 `{YYYY}`、`{YY}`、`{MM}` 和 `{DD}`。
维度键为小写安全标识符，调用值会规范为大写，只允许字母、数字、下划线和连字符。

首个编号预留产生后，方案编码、组织身份、模板、重置周期、位数和起始序号不可修改。需要切换格式时
应创建新方案，避免历史序列语义发生变化。

## 分配事务

`AllocateNumberService` 依次执行：

1. 校验角色、幂等键和请求契约；
2. 锁定并校验方案、医院和组织范围；
3. 由方案、日期分桶和规范维度计算不含业务明文的计数器键；
4. 在 `tabSeries` 中原子创建或递增计数器，并保持事务行锁；
5. 渲染编号并写入不可变 `HRP Number Reservation`；
6. 完成加密幂等响应快照和脱敏审计事件。

服务不调用 `frappe.db.commit()`。任何失败由请求外层事务和领域服务保存点一并回滚。编号字段和预留
令牌均有数据库唯一约束，跨方案格式碰撞也不会产生重复编号。

## 预留记录

预留记录保存业务编号、令牌、方案、业务日期、组织范围、规范维度、摘要、计数器键、序号、方案修订、
模板摘要、分配用户和审计上下文。记录只能由编号服务创建，不能修改、删除、重命名或回收。

API 返回编号与预留令牌；幂等重放返回原响应而不再次递增。普通业务用户只能读取自己的预留，系统管理
员和审计员可以读取全部。COD-024 将在此基础上接入统一组织数据范围解析。

## API

- `CORE-006 POST medops.api.v1.core.numbering.next`：分配编号；
- `CORE-026 POST medops.api.v1.core.numbering.upsert_scheme`：创建或修订方案；
- `CORE-027 GET medops.api.v1.core.numbering.get_reservation`：查询预留。

两个 POST 均要求 `Idempotency-Key`，所有接口支持 `X-Correlation-ID`。公开错误只使用统一
`IONE-CORE` 错误目录。

## 运维与回滚

`ensure_numbering_governance` 在安装和迁移后幂等创建唯一约束及查询索引。升级前必须备份站点数据库。
回滚仅回退代码并重新迁移，保留方案、预留和 `IONE-HRP-NUM-` 计数器，不执行破坏性清理。
