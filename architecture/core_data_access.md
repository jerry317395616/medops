# 核心主数据访问与迁移

角色定义可执行的业务动作；范围决定能操作哪个法人、医院和科室；标准来源及字段权限决定能读取哪些实际值。这三层同时成立才可访问。System Manager、HRP System Manager 的范围保持系统管理语义，Administrator 保持框架超级用户语义；普通业务角色不自动获得全院范围。

## 管理员配置

为业务账号配置 HRP Access Scope：选择法人、医院或科室，添加实际目标 DocType 及所需的 read/create/write/submit/export 操作。写操作同时需要 read。整棵组织版本维护需要医院范围的版本与节点权限，局部科室授权不能替换整棵树。

对主数据更新申请、质量评估和标准映射，还需授予实际 ERPNext 目标的原生读取权限或明确共享，以及相应字段和遮罩权限。共享不会授予高权限字段。服务只记录治理申请或质量状态，不因此授予 ERPNext 标准记录的修改权限。

全局主数据域仅系统管理角色可维护。数据责任人继续在授权范围内创建和审核申请、维护映射及质量规则。人工评估可能创建和更新问题，因此需要规则读取及问题 read/create/write 范围；队列执行时重新检查。

## 查询与单据

“主数据中心”的“主数据受控查询”入口可查询变更申请、外部映射、质量规则和问题，按当前授权逐条验证后再分页，点击记录进入现有表单。查询支持法人、医院、科室、状态、更新日期；范围过大时须缩小条件。接口为 `medops.api.v1.master_data_access.list_records`，只接受固定实体和声明参数，不接受用户身份、任意字段或 SQL。

四种模型的通用 SQL 列表仅 Administrator 可用，其他账号使用上述入口。原因是通用 SQL 查询无法检查每条复制值与质量结论的来源字段，不能以普通列表行过滤替代来源核验。直接读取单据、公开 API 和读取旧幂等响应时仍重新检查当前权限。列表不返回未授权记录的数量，未找到可见记录不代表业务库为空。

组织快照要求能读取完整版本及节点，不能把权限过滤后的残缺树伪装成完整快照。组织标准映射解析检查标准目标的原生读取；医院编号的方案、分配和预留读取使用当前范围，预留仍保留原有主体/审计角色限制。

## 历史质量结论

`evaluation_read_fields` 只保存字段名集合，没有来源值。新问题记录当前检测字段，以后的检测累积字段且不可缩减。读取状态、次数和历史时间时须有所有累计字段的读取权限；修改规则的当前 target_field 不会放开旧字段的结论。

旧版本没有保存历史字段，迁移不猜测具体评估过哪些字段，而以冻结主数据策略的全部允许字段作为保守约束。迁移保留业务值、结论、发现次数和时间，只按标准控制器递增内部修订；重复迁移不再修改。未识别的旧类型保持默认拒绝，由管理员核查。

## 幂等、审计与回退

相同键只允许原始 owner 主体重试。现有键、响应格式、加密快照和留存时间不变；其他主体得到冲突。撤销范围或来源读取后，原主体也不能通过旧键读取响应。业务状态检查在实际写入阶段执行，成功审核的原键重试不会再次审核。

新结果和已完成的重试结果都在领域服务事务内执行当前可见性检查；首次写入的结果字段不可读时，业务写入和幂等预留一并回滚。质量调度对新执行采用主体限定键，原主体已有的旧键继续重试；不同主体独立调度各记录一次评估，不能读取对方的旧响应。

授权及失败审计只记录类型、数量、修订和摘要，不写来源值或申请明细。部署仅在受保护 CI 通过后进行，先备份隔离开发/测试站点，再重复迁移和核对记录数量、业务值与其他站点服务。回退保留约束字段及幂等记录，不能重新开放已知越权。

COD-030 的核心工作台与八张报表仍需继续实现，不能以此查询入口代替。实际医院接口、容量、UAT 和全 HRP 业务覆盖仍为上线门槛。
