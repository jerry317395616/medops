# 核心工作台与八张报表

医衡应用首页为核心工作台，预览当前可见的个人待办、待复核申请、质量问题和服务时限；每栏最多10条，预览不是全院总数。列表扫描有界，存在更多候选时提示进入对应查询缩小条件，不以截断结果输出精确总量。自由文本待办描述不会复制到工作台，避免绕过来源字段权限。

## 医院主数据范围

管理员或数据责任人从工作台菜单“登记主数据”维护医院实际使用的标准记录；可选科室，明确生效、失效日期和启用状态。维护已有登记自动带入当前修订，冲突时刷新记录。标准 ERP 主数据保持由 ERPNext 管理；这里仅登记使用范围，不写财务、库存台账或标准记录。

API `CORE-045` 支持1至100条原子批次，写入需身份、角色、范围、真实目标读取和幂等键；`CORE-048` 只返回当前可见登记。没有自动从共享 Item/Supplier 目录给所有医院建立登记。定时质量扫描改用当前有效登记，升级后须先明确登记需要巡检的目标；人工显式评估仍可选择已授权目标，不会自动登记。

登记的日期筛选基于当前台账的有效区间，不是过去时点的登记快照。重复值检查统一字符宽度、大小写和空白，只有可读的名称参与；完整率以授权且可检测登记为分母，零分母显示不可计算，不显示100%。用户缺少相关来源权限时不能把结果理解为全院目录为空。

## 报表口径

| 编号 | 来源与口径 |
| --- | --- |
| RPT-001 | 同院两个完整已发布组织快照，按稳定组织编码比较。无法读取完整树时拒绝，不把隐藏节点算作新增或删除。 |
| RPT-002 | 当前组织映射及实际 ERP 部门、成本中心名称和停用状态。 |
| RPT-003 | 实际提交至复核的自然分钟；尚未复核为空，负时间序列报配置错误。 |
| RPT-004 | 业务日期内有效、已授权登记及可读名称的重复值。 |
| RPT-005 | 指定外部系统下当前授权登记的有效映射覆盖，显示分子、分母、未覆盖数量和百分比。 |
| RPT-006 | 当前可读问题集合的真实采集事件；数据库聚合每日基线、首次发现、重开、解决、重复和日末未解决。 |
| RPT-007 | 当前授权委托和有效期相交筛选，剩余天数使用站点今日。 |
| RPT-008 | 在原管理角色范围内检查真实单据、用户和动作的当前职责冲突，只读结果不授予执行权限。 |

范围、原生来源、字段/遮罩与导出权限始终实时核验。核心报表禁用准备缓存，普通读取和同步、后台、邮件导出分别使用对应权限；后台任务和撤权后的执行仍需通过检查。趋势要求对选定问题有完整事件授权，不能以缺失事件画出虚假的零值。常规明细候选超过5000时要求缩小过滤范围；趋势直接用授权子查询与SQL聚合，不加载生命周期全部事件。

## 质量历史与迁移

HRP Data Quality Event 仅追加实际采集事件。问题写入与历史在同一事务内提交；事件失败则问题与幂等预留一起回滚。原始观察值不写历史。记录关联当前问题的读取约束，历史不能绕过来源撤权或规则改版后的累计字段限制。

首次迁移创建采集起点 Epoch，并对既有问题建立当前基线。采集前和未来日期显示不可用，当日仍在采集中；不会推测旧问题过去何时首次发现、重复或解决。重复迁移不重复创建基线，不修改既有问题的业务值、次数和业务时间。

部署先备份、暂停本项目任务、保持维护模式，再迁移和校验。回退须保留登记、历史、授权字段和幂等；如旧代码重新暴露已修复越权，保持维护模式，修复后再开放。实际医院接口、容量、UAT及完整 HRP 业务闭环仍待后续验收，参见 production_readiness.md。
