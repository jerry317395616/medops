# COD-003 完善单应用多模块骨架

## 设计依据

- `AGENTS.md`
- `architecture/single_app_architecture.md`
- `architecture/module_registry.yaml`
- `medops/modules.txt`

## 适用范围

本任务只完善 `medops` 单应用中的 36 个模块骨架、模块设置和开发期生成
工具，不创建额外 App，不修改 Frappe、ERPNext 或 Frappe HR 源码，不执行
财务或库存过账，也不直接写 `GL Entry`、`Stock Ledger Entry` 或 `Bin`。

## 模块契约

`architecture/module_registry.yaml` 是唯一模块元数据权威。
`medops.services.module_registry` 提供不可变的 `ModuleRegistry` /
`ModuleSpec` 模型和统一加载、校验、序列化能力。仓库必须满足：

1. 当前注册表恰好包含 36 个唯一模块、唯一包名和唯一递增序号。
2. `modules.txt` 与注册表的名称和顺序完全一致。
3. 每个模块有独立 Python 包、`README.md` 以及 `doctype`、`report`、
   `page`、`workspace`、`services`、`api`、`tests` 七个子包。
4. 不允许存在未注册的 `hrp_*` 模块包。
5. 新模块只能通过开发期命令生成并进入 Git/PR/Press 发布流程。

## 安装与迁移

`after_install` 和 `after_migrate` 调用幂等同步服务：

- 先预检全部 `Module Def` 所有权；发现其他 App 占用时，在任何写入前失败。
- 只创建缺失的 `Module Def`，不删除现有标准记录。
- 创建缺失的 `HRP Module Setting`，修复发生漂移的发布元数据。
- 保留每个站点的 `enabled` 和 `workspace_route` 选择。
- 不调用 `frappe.db.commit()`，事务由 Frappe 安装/迁移边界管理。

## API、权限、幂等与审计

| API | 权限 | 行为 |
| --- | --- | --- |
| `medops.api.v1.modules.list_modules` | 已认证用户 | 只读返回已发布模块与站点启停状态 |
| `medops.api.v1.modules.set_module_enabled` | `System Manager` 或 `HRP System Manager` | 幂等设置模块启停状态 |

写 API 接受或生成 `correlation_id`。目标状态与当前状态相同时不保存、不产生
重复审计；实际变更通过 Frappe `Version`、单据 `Comment` 和站点日志留下
操作者、前后状态及关联 ID。非法模块、非法关联 ID、Guest 和非管理员路径
均在写入前拒绝。

## 开发期模块生成

`bench medops-create-module` 与 `scripts/create_module.py` 复用同一个生成
服务。生成前检查现有模块树；新目录先写入临时位置，再原子替换源文件。
后置校验失败时恢复注册表和 `modules.txt` 并删除新目录，不留下半成品。
