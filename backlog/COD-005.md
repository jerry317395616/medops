# COD-005 建立 CI 单元、集成、前端测试流水线

## 设计依据

- `AGENTS.md`
- `Definition_of_Done.md`
- `architecture/ci_pipeline.md`
- `architecture/quality_tooling.md`
- `architecture/repository_governance.md`
- `resolved_versions.lock.json`

## 交付映射

| 验收项 | 实现 | 证据 |
| --- | --- | --- |
| 单元与静态质量 | `CI / Quality` 调用统一质量入口 | 仓库测试、Ruff、Pyright |
| 前端质量 | ESLint、Prettier、npm audit | 锁定 Node 工具链 |
| 秘密扫描 | Gitleaks 扫描完整 Git 历史 | 固定提交的只读 Action |
| Frappe 集成 | 新建锁定 Bench、迁移并运行 App 测试 | `scripts/ci_integration.sh` |
| 不可绕过 | `Required` 汇总所有必需作业 | `main` 分支保护 |
| 异常路径 | 契约拒绝浮动 Action、高权限触发器和弱化汇总 | 自动化单元测试 |

## 适用性

本任务不新增或修改业务 DocType、Service、API、Workspace、Fixture、角色和
权限，不产生数据库 Patch，也不执行生产发布。写接口权限、业务幂等、业务
审计和台账冲销不适用。CI 本身只创建临时站点，测试完成后销毁。

## 安全与失败处理

- 工作流令牌只有 `contents: read`，不读取仓库 Secret。
- 禁止 `pull_request_target`，第三方 Action 必须固定 40 位 SHA。
- 每个作业设置超时，同一 PR 新运行取消旧运行。
- Quality 失败时 Integration 不启动；Required 对失败、取消和跳过全部失败关闭。
- 集成失败只上传 Bench 日志，不上传数据库、站点配置或私有文件。
- 测试站点 Error Log 非零、锁定提交漂移或工作树变脏都会失败。
