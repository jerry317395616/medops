## 模型、服务、权限和迁移

本任务不新增 DocType、Fixture、数据库 Patch 或 Workspace。错误码是代码/API
契约，必须在请求处理和数据库迁移之前可用，并在所有站点保持一致，因此使用
Git 中的严格 JSON 注册表，而不是生产可编辑模型。

- 模型：`medops.common.error_catalog` 解析不可变定义和翻译覆盖。
- 服务：`medops.services.errors` 是唯一 Frappe 抛出入口与公开服务门面。
- API：管理员只读查询错误目录；不存在新增、修改或删除错误码的 HTTP 接口。
- 权限：`System Manager` 或 `HRP System Manager` 可查目录；原业务接口权限
  不因迁移改变。
- 迁移：无 Schema 和数据迁移，不触发会计、库存或 HR 过账。
- 生产：不连接 Press，不修改 `manager.myyr.top`，不执行生产 migrate。

## 安全、审计与错误契约

公开 `ione_error` 固定包含 `schema_version`、`code`、`category`、`message`、
`error_id` 和 `retryable`。不返回内部 key、原因链、堆栈、文件路径、SQL、
请求参数或用户标识。响应头只包含错误码与随机错误 ID。应用日志仅记录相同
安全元数据和原因类型名称；Frappe 对 500 错误的标准服务端日志策略保持不变。

COD-009 只建立单次错误引用 ID。跨调用关联、请求上下文传播和统一审计上下文
属于依赖本任务的 COD-010，不在本任务提前实现。
