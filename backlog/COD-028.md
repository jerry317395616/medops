# COD-028 SLA 与超时升级

状态：Done（实现与隔离验收已完成；合并仍必须满足受保护 CI，站点发布另有备份及验证步骤）。前置任务为 COD-027。

## 实现范围

- 受控 SLA 策略：目标单据与组织范围、起算字段、响应和处理时限、暂停及完成状态、工作日历和有序升级步骤。
- 复用 ERPNext 的工作时间计算及标准日历、Frappe 待办和通知；不修改这些应用的产品源码。
- ERPNext 的完整 SLA 控制器要求非提交类单据及 `status` 字段。HRP 申请有独立状态和提交生命周期，因此复用其日历计算能力，通过 HRP 适配器接入，避免改写原有工作流。
- 跟踪真实业务单据的计时周期、暂停、恢复、完成及逐级升级，防止重复调度重复派单。
- 策略写入、人工处置具备权限、组织范围、幂等、乐观修订与脱敏审计；升级不自动批准、付款或记账。
- 对策略、日历与组织引用进行验证，支持真实 HTTP 权限与异常路径测试、重复迁移、工作台入口和运行手册。

## 验收要求

时限、工作日与节假日、暂停恢复、跨组织拒绝、并发重复执行、策略修订、角色或日历失效、通知受众权限、错误重试和完成后停止升级均需有证据。正常路径通过不代替异常及恢复测试。

## 实现与证据

- 新增 HRP SLA Policy、HRP SLA Escalation，蓝图、字段目录、索引及工作台入口一致；CORE-034 至 CORE-037 提供受控操作。
- 冻结策略及日历，响应/处理分别计时，支持暂停恢复、结束清理、唯一周期、修订及幂等；按下一个时限节点调度，单周期独立任务。
- 标准 ToDo、Notification Log Alert 复用；不增加共享和业务权限。通知消费时验证持久化待办、当前周期和接收人权限，防止保存点回滚遗留回调。
- 双进程在相同源上使用不同幂等键，复现并修复数据库快照冲突的保存点处理；一次冲突经完整事务重试成功，最终仅一个周期和一条响应待办。
- 301 项纯测试通过；完整隔离测试初版 228 项通过。后续数据库冲突和通知测试共定义 232 项（实际发现 231 项），最终全量结果由本 PR 的必需 CI 产生；通知修复后的 20 项专项和并发验收通过。
- ADR-0023 记录周期和日历决策，ADR-0024 记录数据库冲突和通知队列边界；运维说明见 architecture/sla.md。
