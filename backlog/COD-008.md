## 模型、服务、权限和迁移

本任务不新增业务 DocType、Fixture 或数据库 Patch。ADR 和工程变更必须在应用
安装与迁移之前完成评审，因此机器模型位于版本控制中的策略、Markdown ADR 和
JSON 变更记录，不能建立一个可在生产 Site 中绕过 PR 修改的第二权威。

- 核心：`medops.common.change_governance` 严格解析、交叉校验和生成摘要。
- 服务：`medops.services.change_governance` 只读返回脱敏状态并记录请求事件。
- API：GET，仅 `System Manager` 或 `HRP System Manager`，无 HTTP 写接口。
- CLI：`scripts/change_manager.py` 校验完整仓库和真实 Git 差异。
- 数据：无表结构和业务数据变更，不触发会计、库存或 HR 过账。
- 生产：不连接 Press、不修改 `manager.myyr.top`，无生产迁移。

## 安全、审计与幂等

- API 不返回绝对路径、ADR 正文、决策人、命令输出或环境变量。
- CLI 审计不保存凭据、业务数据或文件内容，POSIX 权限固定为 `0600`。
- Accepted ADR 内容不可改写；删除、改名和非法状态跳转失败关闭。
- 破坏性、单应用边界、权限、上游基线和治理门禁变更强制 Accepted ADR。
- 相同仓库和相同差异重复评估产生相同治理 SHA 与变更 SHA。

## 回滚

回滚本任务代码只移除治理门禁和只读状态 API，不删除 Git、PR、CI 审计，不
修改 Site 数据。已经 Accepted 的 ADR 不通过历史改写回滚；后续决策使用新的
ADR 取代。已实施代码需要回滚时创建新的 COD，并把原变更记录保留为
`Rolled Back`。
