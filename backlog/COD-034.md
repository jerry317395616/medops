# COD-034 预算并发控制（开发中）

COD-033 仍在验收，本分支只进行可并行的前期开发，不代表前置任务完成或可上线。现有纯函数按 BR-BUD-002 标准化预算维度并生成稳定键，按 BR-BUD-001 使用精确十进制计算完整分量并对单个正金额比较；内部行锁原型依据 ADR-0034 复用 Frappe `tabSeries`，尚未通过真实数据库验收或接入财务写服务。负可用额保留以供核对，不能用作成功预占。这些能力不能证明来源完整或授权，不提供 API，也不会改变现有财务动作。

后续纵向切片须完成：事务行锁的真实数据库竞态与恢复测试；结构化预占事件模型和数据库唯一约束；锁内完整重读下达及后续事件、精度/币种和来源权限；幂等命令及追加式记录；审计与持久化人工授权（适用时）；受控 API 和操作入口；同键竞争、不同键隔离、失败回滚、508 重试及恢复；重复迁移与跨站保护。高并发压测须使用确认的目标规模，设计中的100并发不等于医院容量验收。

下达与完整冲销必须参与同一额度锁协议：预占、承诺或实际使用存在时，冲销不得因旧版本或未知事件而释放已使用额度。设计当前使用 company、hospital、organization_unit、fiscal_year、budget_subject、funding_source、project、period_start、period_end 作为 BR-BUD-002 键；序号不作为锁身份，互相重叠的不同期间在共同围栏及验证完成前须禁止业务写入。财务币种与捕获精度在锁内一致性校验，不作为可任意合并的金额。科目、成本中心、组织版本是否还需细分须结合真实医院策略核验，不能无证据扩大或压缩权限范围。释放量只作为完整已核验事件汇总中的一个分量；纯算式不检查事件归属或防重复。

当前没有新增运行 DocType、钩子、迁移、用户权限或 ERPNext 台账写入。后续运行模型必须按标准控制器、事务、权限及追加证据落地；失败或回退不能删除已提交财务事实。COD-033 完成、CI、实际事务和医院专项验收均仍待完成。
