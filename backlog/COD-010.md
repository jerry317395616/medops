## 模型、服务、权限与迁移

本任务不新增 DocType、Fixture、Patch 或 Workspace。审计上下文是数据库连接
失败前也必须可用的短生命周期元数据，使用源码中的不可变模型可避免生产 Site
出现可编辑的第二份真相。

- `medops.common.audit_context`：唯一 ID、载荷和日志字段契约；
- `medops.services.audit_context`：请求/任务钩子、公开服务、脱敏日志和诊断服务；
- `medops.api.v1.audit`：只读 API；
- `medops.hooks`：Frappe v17 原生前后钩子；
- 三个工程管理脚本共用纯 Python ID 校验器。

不修改 Frappe、ERPNext 或 HRMS，不写受保护台账，不修改已提交标准单据。

## 安全与审计

调用方只能提供关联 ID，请求 ID 始终由服务端生成。日志和公开响应不含用户、
邮箱、患者、IP、URL、请求正文、文件路径、站点或凭据。任务载荷在目标函数执行
前被消费。非法输入不回显；错误体只返回安全的新上下文和稳定错误码。
